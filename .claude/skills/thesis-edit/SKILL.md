# 卒論本文・要旨（Word）の修正

対象は `docs/卒論(参考資料)/最新の卒論、要旨、パワポ/` の .docx。書式（見出し・表・目次・箇条書き）を壊さないよう、**必ず `scripts/thesis/` の道具で直す**。docx を新しく作り直したり、XML を手で書き換えたりしない。

## 前提

- Python 3 と Word が入っている PC で行う（リポジトリのルートで実行する）。
- **対象のファイルを Word で開いたままだと上書きできない。** 最初に利用者へ「Word を閉じてください」と伝える。閉じられないときは別名（`_修正N.docx`）で保存し、そのことを報告する。

## 手順

1. いまの文章を確かめる。
   ```
   python scripts/thesis/dump_docx.py "docs/卒論(参考資料)/最新の卒論、要旨、パワポ/<ファイル>.docx"
   ```
   `P`（本文）・`[見出しN]`・`目次`・`表k 行r` の形で出る。直す段落の文章をここから写す。
2. 修正内容ファイルを `scripts/thesis/edits/<今日の日付>_<honbun|youshi>.py` に書く。書き方は `scripts/thesis/apply_edits.py` の冒頭のコメントにある（`d.set` / `d.after` / `d.delete` / `d.heading_after` / `d.table`）。実例は `scripts/thesis/edits/2026-11-17_honbun.py`。
   - 段落は「元の文章」で指定する。長い段落は先頭だけ書いて末尾を `…` にする。
   - 節を足すときは `d.heading_after` を使う（目次の行も足される）。節の名前を変えたら、目次の行も `toc=True` で直す。
   - 表は `d.table(k, 行の一覧)` で、見出し行より下をまるごと指定する。
   - 利用者に確かめないと書けない箇所は、`⟦…⟧` で囲んで黄色の蛍光ペンにし、報告で伝える。
3. 適用する（元のファイルは上書きせず、いったん一時ファイルへ出す）。
   ```
   python scripts/thesis/apply_edits.py "<元.docx>" scripts/thesis/edits/<修正内容>.py "<一時の出力.docx>"
   ```
4. 仕上げる（目次のページ番号を更新し、ページ数を表示する）。
   ```
   powershell -ExecutionPolicy Bypass -File scripts/thesis/finalize.ps1 -Docx "<一時の出力.docx>"
   ```
   - 要旨は **2ページ** に収まっていること。超えたら文章を削る。
   - 本文は、第１章が3ページ目から始まること（目次が1ページに収まっていること）。
5. 問題がなければ、一時の出力で元のファイルを置き換える。PDF が要るときは `finalize.ps1` に `-Pdf` を付ける。

## 守ること

- **修正内容ファイルは、適用した元のファイルとの組で意味を持つ。** `2026-11-17_*.py` は「9月30日提出分 → 11月17日版」の記録なので、最新版には適用しない。最新版を直すときは、新しい日付のファイルを作る。
- 利用者が Word で手直ししているかもしれないので、9月30日版から作り直さず、**いま格納先にある最新版**を元にする。
- 論文に書く事実は、ソースコードで確かめてから書く（`docs/` の資料は根拠にしない）。動作確認の実施状況など、ソースから分からないことは利用者に確かめる。
- 本文を直したら、同じ内容が要旨・スライドにもないかを確かめ、あれば合わせて直す（スライドは `thesis-slides`）。
- 終わったら、`CLAUDE.md` の決まりどおり、変更したファイルの一覧・コミットメッセージ案・PR 説明文案を示す。git の操作はしない。
