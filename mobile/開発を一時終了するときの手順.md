# 開発を一時終了するときの手順（ネイティブ版）

その日の作業を終えるとき・しばらく開発を止めるときに行うことのまとめ。上から順に行う。
最初の準備や、パソコン・スマホを変えたときの手順は [README.md](README.md) を参照。

## 1. 作業内容を残す

- [ ] 確認用に入れたログ（`console.info`、`Log.d` など）で、もう要らないものを消す。消す時期を決めているものは、その時期をメモしておく。
- [ ] `git status` で変更を確かめる。
  - `mobile/android/capacitor.build.gradle` や `capacitor.settings.gradle` が「変更あり」になっていて、中身が改行コード（LF/CRLF）の違いだけなら、`git checkout -- mobile/android` で戻してよい。
- [ ] `feature/xxxx` ブランチでコミットし、push する（`main` には直接コミットしない）。
- [ ] どこまで進んだか、次に何をするかをメモしておく（PR の説明文や、自分用のメモなど）。

## 2. スマホのアプリを片付ける

- [ ] **テスト用に登録したお薬（2〜3分後の時刻など）を「お薬」画面から削除する。** アプリを閉じても、Android Studio を終了しても、スマホを再起動しても、アラームは登録した時刻に毎日鳴り続ける。消したら、マイページの「次のアラーム」に出ないことを確かめる。
- [ ] 鳴っているアラームや「あとで」（5分後にもう一度鳴る）が残っていないか確かめる。
- アプリ自体はアンインストールしなくてよい。次回は、スマホのアプリ一覧の「お薬手帳」のアイコンから開ける。

## 3. Android Studio を止める

- [ ] 上部の **■（Stop 'app'）** を押して、実行中のアプリを止める。スマホの最近使ったアプリの一覧からアプリを消していた場合は、もう止まっているので押さなくてよい。
- [ ] 「File」→「Exit」で Android Studio を終了する。保存されていない編集があれば、保存してよいか聞かれる。
- ルートで `npm run dev` などのサーバーを動かしていたら、Ctrl + C で止める。

## 4. スマホとパソコンの接続を外す

- [ ] USB ケーブルを抜く（Android Studio を終了してからなら、そのまま抜いてよい）。
- 「USB デバッグ」は、オンのままでも開発には困らない。ただし、知らないパソコンにつなぐ機会があるなら、開発者向けオプションで「USB デバッグ」をオフにしておくと安全。
  - オフにしても、このパソコンの許可は残る。次にオンに戻したとき、もう一度「USB デバッグを許可しますか？」が出ないことがある。

## 次に再開するとき

1. Android Studio を開く（前回のプロジェクト `mobile/android` が自動で開く。開かないときは「Open」で選ぶ）。
2. ほかの人の変更を取り込んだ（`git pull` した）ときは、`mobile/` で次を実行する。`mobile/package.json` が変わっていなければ `npm install` は要らない。
   ```
   cd mobile
   npm install
   npx cap sync android
   ```
3. スマホを USB でつなぎ、上部で端末を選んで ▶（Run）を押す。

## 補足：アプリを最近使ったアプリの一覧から消したとき

- アプリのプロセスが終わるので、Android Studio の実行（Run）もそこで終わる。確かめ方は次のとおり。
  - 上部のツールバー：実行中は ▶ の近くに赤い ■（Stop 'app'）が出る。終わると ■ が消え（または灰色になり）、▶ だけに戻る。
  - Logcat（左下の猫の顔のようなアイコン）：`PROCESS ENDED (プロセス番号) for package jp.mediwatch.app` という行が出る。
  - 「Run」タブ（左下の ▷ のアイコン）には、インストールと起動の記録が出るが、終了したことは出ないことが多い。
- アプリはスマホに入ったままなので、また使うときはアプリ一覧の「お薬手帳」のアイコンをタップすればよい。Android Studio から ▶ で入れ直す必要はない。
  - ただし、`public/` やネイティブのコードを直したときは、`npx cap sync android` → ▶ で入れ直さないと変更は反映されない。
- 一覧から消しても、予約済みのアラームは止まらない（README の「動作の確認」で確かめる状態の1つ）。
- アイコンから開いたあとも、Android Studio の「Logcat」で `MediAlarm` を検索すればネイティブ側のログを見られる。画面のコンソールは、パソコンの Chrome で `chrome://inspect` を開いて見る。
