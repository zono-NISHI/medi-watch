# 9月提出の論文と、現在のシステムの差

2026-11-17 に、9月30日提出分の卒論本文・要旨を現在のソースコードと照らし合わせ、修正版を `最新の卒論、要旨、パワポ/` に作った。そのときに分かった差をまとめる。発表資料（パワポ）で「提出後に何が変わったか」を説明するときの材料になる。

## 論文の記述と食い違っていた点（修正版で直したもの）
- **利用者の役割**: 論文は「患者／家族・介護者の2つの役割を登録時に選ぶ」としていた。現在は役割で画面を分けず、「家族に見守ってもらう」「家族を見守る」の2つの機能を利用者ごとに選ぶ（1つのアカウントで両方を兼ねられる）。
- **認証**: メールで届く6桁の確認コードによるメール確認と、パスワード再設定が加わった。論文の `supabaseAnon` は、リクエストごとに作る `createAuthClient()` に変わっている。
- **画面数**: 6画面 → 10画面（表紙・新規登録・ログイン・メール確認・パスワード再設定・ホーム・お薬・記録・見守り・マイページ）。「家族」画面は「見守り」画面になった。
- **服薬スケジュール**: 論文は「曜日・事前通知時間を薬ごとに設定できる」としていたが、画面で設定できるのは時刻と食前・食後だけ（毎日・5分前で固定。DBの列はある）。
- **時刻の扱い**: 論文の「今後の課題」にあった「タイムゾーン処理の厳密化」は解決済み（`src/lib/jst.js`）。
- **QRコードの解析**: 「簡易実装」から、実データ（Shift_JIS、薬品・用法・用法補足のレコード）に合わせた実装に変わった。
- **通知**: 「見守りの終了」の通知が加わり、4種類 → 5種類。
- **服薬アラーム**: 「時刻になると音声で読み上げる」から、全画面のアラーム（音・読み上げ・振動、あとで5分）に変わった。録画は30秒で自動的に記録される。
- **新しく加わったもの**: 記録の追加・訂正、招待コードの作り直し、使う機能の選択、Android版（Capacitor＋Java のアラーム）。
- **動作確認**: 論文は「開発環境で確認する。ほとんどが未実施」としていた。現在は Render にデプロイしたサイトで確認している。

## 考察として述べられること
- 9月の時点で「実装済みだが未確認」と書いた機能は、公開環境で動かすと多くの不具合が見つかった（UTC の時刻ずれ、QRコードの文字コードとレコード構造、端末側だけで起きる通知表示のエラー）。「実装した」と「動く」のあいだには大きな差があり、論文に書いた仕様そのもの（役割の分け方など）も、動かしてみて初めて見直しが必要だと分かった。
- 論文とシステムを別々に直していくと、今回のように記述が食い違う。アプリの挙動は `利用者目線のアプリ挙動一覧.md` をソースコードと同時に更新する運用にしていたため、論文の修正ではこのファイルを突き合わせの基準にできた。仕様の「正」を1か所に決めておくことが、文書の保守にも有効だった。

## 論文とスライドを「作り直せる形」で管理するようにした（2026-11-17）
- 最初の修正では、食い違いの洗い出しと、Word の書式を保ったまま書き換える道具づくりに時間がかかった。そこで道具を `scripts/thesis/` に残し、手順を Claude Code のスキル（`.claude/skills/thesis-check`・`thesis-edit`・`thesis-slides`）にまとめた。
- Word の修正は「どの段落をどう直したか」を修正内容ファイル（`scripts/thesis/edits/`）として残す。あとから、いつ・何を直したかをたどれる。
- 発表スライドは、文言と話す内容を1つのスクリプト（`scripts/thesis/slides/build_slides.js`）に書き、そこから作る。配色はアプリと同じ色にそろえた。
- 考察: アプリのコードと同じく、文書も「手で直した結果」だけを残すと、次に直す人（未来の自分）が経緯を追えない。直し方を記録として残すと、同じ作業を短い時間で繰り返せる。一方、PowerPoint で直接直した内容はスクリプトから作り直すと消えるため、「どちらを正とするか」を決めておく必要がある（手順書に明記した）。

## 修正版で本人に確認して決めた点（2026-11-17）
- 表5.1（動作確認の実施状況）の「状況」欄は、12項目すべて「確認済み」とした。
- 5.2節の「iOS端末での検証と第三者による試用評価は実施できていない」は、そのまま載せる。

- 「今後の課題」から CSP（コンテンツセキュリティポリシー）の項目を外した。`server.js` で無効にしたままである事実は変わらないが、今後の課題は主なものを挙げれば足り、発表で説明しにくい項目を残す必要はないと判断した。
- 要旨の「開発環境」に「メール送信：Brevo」を加えた。Supabase・Render と同じく、システムを動かすのに欠かせない外部サービスであるため。
