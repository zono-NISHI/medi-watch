# 機能の多さと高齢者の使いやすさの両立

## 経緯
- 最初は登録時の役割（患者／家族）で画面を分けていた。
- `29bdf4d`（0004）で、1人が「見守る側」と「見守られる側」を兼ねられるようにした。実際の家族関係（自分も薬を飲みながら親を見守る、など）に合わせるためである。
- しかし、すべての利用者に両方の機能を見せると、使わない操作（招待コードの入力、表示の切り替えなど）が画面に増え、高齢の利用者の押し間違いや混乱の元になる。
- そこで `3d874e3`（0005）で、登録時に使う機能を選んでもらい、使わない操作を画面から隠すようにした。
- 見守り画面の家族の切り替えも、プルダウン（`53e01e4`）から2つの大きなボタン（`669b41b`）に作り直した。

## 考察
- 「できることを増やす」ことと「画面を分かりやすく保つ」ことは、しばしば対立する。本アプリでは、機能はすべて実装したうえで、利用者ごとに見せる範囲を絞ることで両立を図った。
- 画面から隠すだけでは、データ上は見守りが続いているのに利用者からは見えない、という食い違いが起こりうる。そのため、ルールは画面だけでなくデータベース（トリガー）でも守るようにした。使いやすさのための工夫が、データの正しさを損なわないよう配慮する必要があった。
- プルダウンは画面を省スペースにできるが、中に何があるか見えず、高齢者には操作が分かりにくい。選択肢が少ないときは、ボタンを並べて常に見えるようにするほうがよいと考えられる。
- 利用者による評価（実際の高齢者に使ってもらうこと）は今後の課題である。

## 補足：見守りの解除を相手に知らせるかどうか
- 見守りを外したことを相手に通知すると、見守っていた人の不安や誤解は減る。一方で、見守られている人にとっては「外したことが相手に伝わる」ため、気軽に外しにくくなる（家族関係に気をつかう）という面もある。
- 本アプリでは、見守る側が状況を把握できることを優先して通知することにし、そのかわり外す側の確認ダイアログで「相手にお知らせが届く」ことを事前に示した。知らせるかどうかを利用者が選べるようにする案もあるが、高齢の利用者には選択肢が増えるほど分かりにくくなるため、今回は採用しなかった。
