# 高齢の利用者に向けた画面と操作の工夫

## 1. 場面ごとに必要なボタンだけを出す
- 関連コミット: `10c98dc`
- 服薬を記録する画面で、ボタンを1つにまとめるのではなく、場面に応じて出すボタンを変えた。
  - カメラ起動前: 「カメラを起動する」「映像なしで『飲んだ』を記録」「今回はスキップする」
  - 録画中: 「飲みました（映像つきで記録する）」「今回はスキップする」（紛らわしい「映像なしで記録」は隠す）
- ボタン名に「映像つきで記録する」と書き、違いがひと目で分かるようにした。
- `hidden` を付けた要素が必ず非表示になるCSSのルールを追加し、ほかの画面の同じ不具合もまとめて防いだ。

## 2. 録画は30秒で自動的に記録する
- 関連コミット: `af4645d`
- 録画を止めるボタンを押し忘れても記録できるように、録画は30秒で自動的に終わって記録されるようにした。

## 3. アプリを開いているあいだの服薬アラーム
- 関連コミット: `ae4db5f`（`public/js/alarm.js`）
- 服薬時刻になると、画面いっぱいに「カメラを起動する」ボタンを出し、記録するか「あとで」を押すまで音・読み上げ・振動を繰り返す。プッシュ通知だけでは気付きにくい利用者を想定した。
- ログイン後のすべての画面で動き、ホーム以外の画面からでもボタン1つで記録画面へ移動できる。
- 「あとで」は5分後にもう一度知らせる。服薬時刻から60分を過ぎたら、アラームではなくホームの案内に切り替える。

## 4. 記録タブを見やすくした
- 関連コミット: `331349d`, `80791a0`, `ed8a63a`
- 1日ごとに枠で区切り、新しい順に並べた。記録した時刻を大きく表示した。
- 予定時刻を過ぎても記録がない予定には「飲み忘れ」のバッジを付け、ひと目で分かるようにした。スキップにも記録時刻を表示した。
- 1日ごとの枠は、最初は背景より少し濃い紙色と薄い罫線で作ったが、ページの背景と色が近く、区切りが分かりにくかった。そこで枠線を藍色の太線にし、日付の見出しを藍色の帯に白い文字で表示するように改めた。色の明暗の差（コントラスト）をはっきりさせることで、視力が落ちてきた高齢の利用者でも、どこからどこまでが同じ日の記録かを見分けやすくしている。家族の記録を表示しているときは、枠と帯もテラコッタ色に変わり、ほかの画面の配色とそろえている。
- 記録のカードは「時刻｜薬の名前と状態｜ボタン（映像を見る・編集）」を横に並べていたが、スマートフォンでは「映像を見る」ボタンが出ると薬の名前の欄が細くなり、名前が1〜2文字ずつ折り返して読みにくくなっていた。パソコンの画面では気づかず、実際のスマートフォンで開いて分かった問題である。そこで、横幅480px以下の画面ではボタンをカードの下の段に横並びで置き、時刻と薬の名前に横幅いっぱいを使わせるようにした（`public/css/logs.css` のメディアクエリ）。ボタンも横幅いっぱいに広がるので、指で押しやすくなった。
- 記録のカードには薬の名前しか出ておらず、「何錠飲む予定だったか」はお薬タブを開かないと分からなかった。家族が記録を見て確かめるときにも、量が分かるほうが安心できる。そこで、お薬タブで登録した用量・単位（例：「1 錠」）を薬の名前の下に小さく表示するようにした（`public/js/pages/logs.js` の `renderLogCard`）。表示の形はホーム・お薬タブと同じ「用量 単位」にそろえ、どの画面でも同じ見え方になるようにした。データは記録の一覧を取る API がすでに返していたため、サーバー側の変更は要らなかった。
  - ただし、表示しているのは「いま登録されている」用量であり、記録した当時の用量ではない。あとで用量を変えると、過去の記録の表示も新しい用量に変わる。当時の量を正確に残すには、記録を作るときに用量を `medication_logs` へ写し取っておく必要がある（今後の課題）。

## 5. 入力の手間と間違いを減らす
- 関連コミット: `c8ae8ea`, `b03b444`, `0fd2d00`
- お薬の単位（錠・包など）を自由入力ではなくプルダウンで選べるようにした。
- パスワード入力欄に「表示／非表示」の切り替えを付け、入力した内容を確かめられるようにした。
- 登録画面の入力チェックとエラーの表示を見直した。

## 6. 使わない機能は画面に出さない
- 関連コミット: `3d874e3`（マイグレーション `0005_watch_features.sql`）
- 登録時に「使い方」（見守られる／見守る／自分のお薬の管理だけ）を選んでもらい、使わない操作（招待コードの入力や家族への表示の切り替えなど）を画面に出さないようにした（表示中の人が分かるよう、「自分」のボタンだけは常に出す。7. を参照）。あとからマイページで変更できる。
- 画面から隠すだけでなく、データベースのトリガーでも「機能を使わない人が見守りを始める」「見守りの相手がいるのに機能を OFF にする」ことを止めている（画面から消えたのに見守りが続く、という食い違いを防ぐ）。

## 7. 見ている人が自分か家族かを、色で区別する
- 関連コミット: `ae4db5f`, `53e01e4`, `669b41b`（`public/js/viewTarget.js`）
- ホーム・お薬・記録のタブで、表示する人（自分／見守っている家族）を切り替えられるようにした。選んだ人はタブを移っても引き継ぐ。
- 家族の情報を表示しているあいだは画面の配色を変え、自分の情報と取り違えないようにした。
- 見守り画面の「見守っている／見守られている」家族の切り替えは、最初はプルダウンで作ったが、操作が分かりにくいため2つの大きなボタンに改めた。
- 切り替えのボタンは、最初は見守っている家族がいるときだけ表示していた。しかし、家族の画面を見たことがある人や、あとから見守りを始めた人にとっては、ボタンが出たり消えたりすると「いま誰の情報を見ているのか」が分かりにくくなる。そこで、見守っている家族がいない場合も「自分」のボタンだけは選択された状態で常に表示し、自分のお薬の情報を見ていることが一目で分かるようにした（`public/js/viewTarget.js` の `renderSwitcher`）。切り替える相手がいないので、押しても表示は変わらない。

## 8. 招待コードを書き写しやすくした
- 関連: `0006_regenerate_invite_code.sql`、`src/routes/careGroups.js`
- 招待コードは、電話や紙で家族に伝えることも想定される。以前は16進数（0〜9 と a〜f）の小文字だった。
- 見間違えやすい文字（0 と O、1 と I と L）を使わない、英大文字と数字の8文字にした。
- 入力するときは大文字・小文字を区別せず、書き写したときに入りやすい空白やハイフンも無視するようにした（入力欄は最初から大文字になるようにした）。
- 区別しないことを入力欄の上に「英字は大文字・小文字のどちらで入力しても大丈夫です。」と書いた。書いておかないと、利用者は大文字・小文字を気にして入力に時間がかかったり、小文字で打ったものを消して打ち直したりしてしまう。システムが受け入れる入力の幅は、画面で伝えて初めて利用者の負担を減らせる。
- 文字の種類を31種類に絞っても、8文字で約8,500億通りあり、当て推量で他人のコードを当てるのは現実的でない。

## 9. 登録画面の「使い方」を、基本機能と追加機能に分けて問うようにした
- 関連: `public/signup.html`
- 以前は「どのように使いますか」という問いに、「家族に見守ってもらう」「自分のお薬の管理だけ」「家族を見守る」の3つを同列に並べていた。
- しかし、お薬の記録はどれを選んでも使える基本機能であり、見守りの2つは追加の機能である。「〜だけ」という言い方のせいで、他を選ぶとお薬の管理が含まれない（制限される）ように読めてしまっていた。説明文にも「ご自分のお薬の記録もできます」が書かれている選択肢と書かれていない選択肢があり、揃っていなかった。
- そこで、選択肢の上に「お薬の記録・服薬のアラームは、どれを選んでもお使いいただけます。」と共通の前置きを1か所だけ置き、問いを「ご家族とどのように使いますか」に絞った。
- 「自分のお薬の管理だけ」は「今は家族とつながらない」と言い換え、何も足さない選択肢として最後に置いた。「見守りはあとからマイページで始められます」と添え、選んでも後戻りできることを伝えた。
- 選択肢の中身（保存される設定）は変えず、文言と並び順だけを直した。

## 新規登録の「使い方」の選択肢を、選んだものがひと目で分かる形にした

- もとは本物のラジオボタンを隠し、選んだカードの枠の色と、ごく薄い背景色だけで選択中を示していた。色の差が小さく、高齢の方には「どれを選んでいるか」が分かりにくかった。
- 選択中を色の違いだけに頼らず、次の3つを重ねて示すようにした。
  - カードの左に大きな丸印を置き、選ぶと藍色に塗られて「✓」が付く（形の変化）。
  - 選んだカードの背景をはっきりした薄い藍色にし、枠を太くする（面積の大きい変化）。
  - 「選択中」という文字の札を出す（文字による明示）。
- 色覚に特性のある方や、画面が見えにくい方でも、形と文字で区別できる。丸印と札は `aria-hidden` にして、読み上げは従来どおりラジオボタンの選択状態で伝わるようにした（読み上げが二重にならない）。
- 見出しの文字を大きく（24px）し、説明文も補助色のままでは薄いため、選んだカードでは本文色に濃くした。

## 「あとで変えられる」という案内を、選ぶ前に・対象をはっきりさせて示した

- もとは選択肢の一番下に「あとから「マイページ」で変更できます。」とだけ書いていた。主語がなく、下に続くお名前やメールアドレスの欄のことにも読めた。また、選び終わってから目に入る位置だった。
- 「あとで変えられる」は、選ぶ前に知っていれば迷わずに済む情報なので、選択肢の上の前置きに移した。高齢の方が「間違えたら取り返しがつかない」と悩んで手が止まるのを防ぐねらい。
- 文言は「ここで選んだ使い方は、あとからマイページの「使う機能」で変えられます。」とし、何を（使い方）・どこで（マイページの「使う機能」）変えられるかを、実際の見出し名まで書いた。あとで探すときの手がかりになる。
- マイページでは「見守る」「見守ってもらう」を両方選べるが、登録画面では1つしか選べない。この食い違いで両方使いたい人が迷わないよう、「両方使いたい方も、まずはどちらか1つを選んでください。」と添えた。
- 「今は家族とつながらない」の説明に入っていた同じ趣旨の一文（見守りはあとからマイページで始められます）は削り、案内を1か所にまとめた。


## 重なって開いた画面の上にも、お知らせ（トースト）を出す
- 関連: `public/js/ui.js`（`showToast` / `placeToastArea`）
- 問題: お薬の編集画面などは `<dialog>` の `showModal()` で開いている。この方法で開いた画面はブラウザの「最前面の層（トップレイヤー）」に表示されるため、ページ側に置いたトーストは `z-index` をいくら大きくしても裏に隠れてしまう。同じ時刻の服薬スケジュールを2つ入れて保存したときのエラーが、編集画面の裏に出て読めなかったことで気づいた。
- 工夫:
  - モーダルを開いているあいだは、トーストの置き場所をそのモーダルの中に移すようにした。トーストを出す共通の関数を1か所直すだけで、すべての画面に効く。
  - モーダルを閉じたときは置き場所を元に戻し、「登録しました。」のように、閉じる直前に出したお知らせが一緒に消えないようにした。
  - トーストを最前面に出す別の方法として Popover API もあるが、iPhone では iOS 17 以降でないと使えない。古い端末を使う高齢者もいることを考え、採用しなかった。
  - エラーのトーストは、読み終わる前に消えないよう、表示時間を約3秒から約6秒に延ばした。成功のお知らせは短いままにした。
- 画面の中にエラー文を出す方法（入力欄のそばに表示する）も検討した。しかし、重なっている行にはすでに赤茶色の枠を付けていて、どこを直せばよいかは分かる。トーストと同じ内容を2か所に出すと、かえって分かりにくくなるため、採用しなかった。

## 記録画面の日付の欄を、スマートフォンでも「押して選ぶ欄」と分かるようにした
- 関連: `public/logs.html`、`public/css/logs.css`（`.date-picker` / `.date-placeholder`）、`public/js/pages/logs.js`
- 問題: 日付の絞り込みには `<input type="date">` を使っている。パソコンのブラウザでは未選択でも「年/月/日 📅」と表示されるが、スマートフォン（特に iPhone の Safari）では未選択の欄が何も書かれていない空白になり、日付を選べる欄だと気づきにくかった。日付の入力欄には `placeholder` 属性が効かないため、ブラウザの機能だけでは案内を出せない。
- 工夫:
  - 日付を選んでいないあいだだけ、欄の上に「📅 日付を選ぶ」という案内を重ねて表示するようにした。案内は `pointer-events: none` にして、押すと下の日付欄がそのまま反応するようにした。
  - 案内を重ねるとパソコンでは📅のボタンが隠れるため、欄のどこを押してもカレンダーが開くようにした（`showPicker()`。使えない古いブラウザでは標準の動きに任せる）。
  - 「日付」「状態」の見出しを欄の上に付け、何を絞り込む欄なのかを言葉でも示した。
  - 端末ごとに表示が変わらないよう、パソコンとスマートフォンで同じ案内を出すことにした。

## アプリのアイコンを「お薬」と「時間・見守り」が一目で分かる図柄にした
- 関連: `scripts/generate-icons.ps1`、`public/assets/`（`icon-192.png` / `icon-512.png` / `icon-maskable-512.png` / `apple-touch-icon.png` / `favicon-32.png` / `badge-96.png`）、`public/manifest.json`、`public/sw.js`、`mobile/android/app/src/main/res/mipmap-*/`
- 問題: もとのアイコンは藍色の地に白い円を描いただけで、何のアプリか分からなかった。Android アプリは Capacitor の初期アイコンのままだった。高齢の方はスマホのホーム画面でアプリを「絵」で探すことが多く、ほかのアプリと見分けにくいと、お薬の時間にすぐ開けない。
- 工夫:
  - 図柄は「時計の文字盤」の上に「カプセル」を重ねたものにした。カプセルで「お薬のアプリ」、文字盤で「決まった時間に飲む・アラームで知らせる・家族が見守る（watch）」ことを表し、アプリ名 medi-watch の意味を1枚で伝えるようにした。
  - 色は画面と同じ藍色・紙色・テラコッタ橙だけを使い、アプリを開く前と後で印象がそろうようにした。
  - 小さく表示されても形が分かるよう、文字盤の目盛りは 12・3・6・9 時の4本だけにし、細かい針や文字は入れなかった（32px のファビコンでもカプセルと分かる）。
  - Android の端末やランチャーはアイコンを丸・角丸・しずく形などに切り抜く。切り抜かれても欠けないよう、PWA 用には全面を塗った「maskable」アイコン（図柄は中央 80% に収める）を、Android アプリ用には前景と背景色を分けた「アダプティブアイコン」（図柄は中央 66dp に収める）を用意した。
  - Android の通知のステータスバーに出る「バッジ」は、画像の透明でない部分だけを白く塗って表示される。もとは通常のアイコンをそのまま使っていたため白い四角になっていたので、白いカプセルの形だけを透明の地に描いた専用の画像にした。
  - アイコンは画像編集ソフトで描かず、図形の座標を書いたスクリプトから全サイズ（Web 版6種類・Android 版15枚）を作るようにした。Windows 標準の機能（System.Drawing）だけで動くので、Node や Python が入っていない学校のパソコンでも作り直せる。色や大きさを変えても、全サイズの見た目がずれない。
