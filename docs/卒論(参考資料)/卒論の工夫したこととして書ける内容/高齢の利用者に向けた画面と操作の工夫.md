# 高齢の利用者に向けた画面と操作の工夫

## 1. 場面ごとに必要なボタンだけを出す
- 関連コミット: `10c98dc`
- 服薬を記録する画面で、ボタンを1つにまとめるのではなく、場面に応じて出すボタンを変えた。
  - カメラ起動前: 「カメラを起動する」「映像なしで『飲んだ』を記録」「今回はスキップする」
  - 録画中: 「飲みました（映像つきで記録する）」「今回はスキップする」（当初は、紛らわしい「映像なしで記録」を隠していた）
- ボタン名に「映像つきで記録する」と書き、違いがひと目で分かるようにした。
- （後日の見直し）録画中にも「飲みました（映像なしで記録する）」を出すように改めた。
  - きっかけ: ネイティブ版（Android アプリ）のアラームでは「カメラを起動する」を押すとすぐにカメラが起動するため、カメラ起動前の画面を通らない。録画中に「映像なし」を隠していると、映像を残したくない人は「×」で一度閉じるしかなく、その先の画面で迷うという意見が出た。
  - 紛らわしさへの対応: 録画中は2つのボタンを「飲みました（映像つきで記録する）」「飲みました（映像なしで記録する）」と同じ形の言い方にそろえ、色（塗りつぶし／枠線だけ）で主・従を分けた。
  - ボタンが1つ増える分、録画中は映像の枠を低くし（縦長 3:4 → 画面の高さの約 34%）、説明文も短くして、3つのボタンがスクロールせずに見えることを優先した。映像は服薬の様子が分かれば足りるため、枠の大きさよりも操作のしやすさを取った。
  - 「隠して迷わせない」方針は、入り口（どの画面から来るか）が変わると、かえって行き止まりを作ることがある。場面ごとに出すボタンを決めるときは、その場面に来る経路をすべて確かめる必要がある。
- `hidden` を付けた要素が必ず非表示になるCSSのルールを追加し、ほかの画面の同じ不具合もまとめて防いだ。

## 2. 録画は30秒で自動的に記録する
- 関連コミット: `af4645d`
- 録画を止めるボタンを押し忘れても記録できるように、録画は30秒で自動的に終わって記録されるようにした。

## 3. アプリを開いているあいだの服薬アラーム
- 関連コミット: `ae4db5f`（`public/js/alarm.js`）
- 服薬時刻になると、画面いっぱいに「カメラを起動する」ボタンを出し、記録するか「あとで」を押すまで音・読み上げ・振動を繰り返す。プッシュ通知だけでは気付きにくい利用者を想定した。
- ログイン後のすべての画面で動き、ホーム以外の画面からでもボタン1つで記録画面へ移動できる。
- 「あとで」は5分後にもう一度知らせる。服薬時刻から60分を過ぎたら、アラームではなくホームの案内に切り替える。
- （後日の追加）アラームで「何を・いくつ飲むか」まで声で伝えるようにした。
  - きっかけ: ネイティブ版（Android アプリ）のアラームは、スマホのアラーム音が鳴るだけだった。音だけでは、目覚ましなのか、お薬の知らせなのかが分からず、画面を見に行かないと飲むお薬も分からない。Web 版には読み上げがあったが、お薬の名前だけで、用量は言っていなかった。
  - 対応: 「お薬の時間です。○○を3錠、□□を1包服用してください。」と、名前と用量を読み上げるようにした。画面の小さな文字を読まなくても、耳で聞くだけで飲む量が分かる。同じ時刻のお薬が複数あれば、1つの文にまとめて読み上げる。
  - 読み上げる文は1か所（`public/js/alarm.js` の `medAnnouncement`）で作り、Web 版のアラーム・撮影画面で共通に使う。ネイティブ版には、お薬ごとの「○○を3錠」の部分を予定と一緒に渡し、Java 側（`AlarmRinger.announcement`）で同じ形の文に組み立てる。どこで聞いても同じ言い方になるようにした。
  - ネイティブ版は、Android の読み上げ機能（TextToSpeech）を使う。アラームの音と声が重なると聞き取りにくいので、「アラームの音 → 読み上げ → アラームの音 → …」と交互にした。まず音で気付いてもらい（約3秒）、そのあと声で内容を伝える。
  - 読み上げているあいだ、アラームの音は「止める」のではなく「音の大きさを0にする」ことにした。再生を止めると、画面が消えているときに端末が省電力で眠り、続きが鳴らなくなるおそれがあるためである。また、読み上げの終わりの知らせが届かなかった場合でも、一定時間（40秒）でアラームの音を必ず戻すようにした。「読み上げを足したせいで、アラームが鳴らなくなる」ことが起きないようにするためである。
  - 読み上げも、アラームの音と同じ「アラーム」の音量で鳴らす。着信音やメディアの音量を0にしている人でも聞こえる。
  - 端末に日本語の読み上げ機能が入っていない場合は、これまでどおり音と振動だけで知らせる（読み上げは「あれば使う」付加機能とし、無くても知らせる機能そのものは失われないようにした）。

## 4. 記録タブを見やすくした
- 関連コミット: `331349d`, `80791a0`, `ed8a63a`
- 1日ごとに枠で区切り、新しい順に並べた。記録した時刻を大きく表示した。
- 予定時刻を過ぎても記録がない予定には「飲み忘れ」のバッジを付け、ひと目で分かるようにした。スキップにも記録時刻を表示した。
- 1日ごとの枠は、最初は背景より少し濃い紙色と薄い罫線で作ったが、ページの背景と色が近く、区切りが分かりにくかった。そこで枠線を藍色の太線にし、日付の見出しを藍色の帯に白い文字で表示するように改めた。色の明暗の差（コントラスト）をはっきりさせることで、視力が落ちてきた高齢の利用者でも、どこからどこまでが同じ日の記録かを見分けやすくしている。家族の記録を表示しているときは、枠と帯もテラコッタ色に変わり、ほかの画面の配色とそろえている。
- 記録のカードは「時刻｜薬の名前と状態｜ボタン（映像を見る・編集）」を横に並べていたが、スマートフォンでは「映像を見る」ボタンが出ると薬の名前の欄が細くなり、名前が1〜2文字ずつ折り返して読みにくくなっていた。パソコンの画面では気づかず、実際のスマートフォンで開いて分かった問題である。そこで、横幅480px以下の画面ではボタンをカードの下の段に横並びで置き、時刻と薬の名前に横幅いっぱいを使わせるようにした（`public/css/logs.css` のメディアクエリ）。ボタンも横幅いっぱいに広がるので、指で押しやすくなった。
- 記録のカードには薬の名前しか出ておらず、「何錠飲む予定だったか」はお薬タブを開かないと分からなかった。家族が記録を見て確かめるときにも、量が分かるほうが安心できる。そこで、お薬タブで登録した用量・単位（例：「1 錠」）を薬の名前の下に小さく表示するようにした（`public/js/pages/logs.js` の `renderLogCard`）。表示の形はホーム・お薬タブと同じ「用量 単位」にそろえ、どの画面でも同じ見え方になるようにした。データは記録の一覧を取る API がすでに返していたため、サーバー側の変更は要らなかった。
  - ただし、表示しているのは「いま登録されている」用量であり、記録した当時の用量ではない。あとで用量を変えると、過去の記録の表示も新しい用量に変わる。当時の量を正確に残すには、記録を作るときに用量を `medication_logs` へ写し取っておく必要がある（今後の課題）。
- 同じ日の中の並び順を、予定時刻の早い順（朝→夜）に改めた（2026-11-17）。当初は全体を予定時刻の新しい順に並べていたため、1日の枠の中でも「夜→昼→朝」の順になり、ホーム画面の「今日の予定」（朝→夜）とは逆だった。ネイティブ版を使った人から「日付ごとの記録は、服用時刻の早い順にしてほしい」という意見が出たため、日付のまとまりは新しい順（今日が一番上）のまま、枠の中だけを昇順にした（`public/js/pages/logs.js` の `renderLogs`）。「最近の日をすぐ見たい」ことと「1日の流れを朝から順に追いたい」ことは、並べる単位（日／時刻）を分けて考えれば両立できる。画面によって並び順が違うと、利用者はそのたびに読み方を切り替えることになるため、1日の中の並びはどの画面でも同じにそろえた。

- 関連コミット: `c8ae8ea`, `b03b444`, `0fd2d00`

- パスワード入力欄に「表示／非表示」の切り替えを付け、入力した内容を確かめられるようにした。

## 6. 使わない機能は画面に出さない
- 関連コミット: `3d874e3`（マイグレーション `0005_watch_features.sql`）
- 登録時に「使い方」（見守られる／見守る／自分のお薬の管理だけ）を選んでもらい、使わない操作（招待コードの入力や家族への表示の切り替えなど）を画面に出さないようにした（表示中の人が分かるよう、「自分」のボタンだけは常に出す。7. を参照）。あとからマイページで変更できる。
- 画面から隠すだけでなく、データベースのトリガーでも「機能を使わない人が見守りを始める」「見守りの相手がいるのに機能を OFF にする」ことを止めている（画面から消えたのに見守りが続く、という食い違いを防ぐ）。

## 7. 見ている人が自分か家族かを、色で区別する
- 関連コミット: `ae4db5f`, `53e01e4`, `669b41b`（`public/js/viewTarget.js`）
- ホーム・お薬・記録のタブで、表示する人（自分／見守っている家族）を切り替えられるようにした。選んだ人はタブを移っても引き継ぐ。
- 家族の情報を表示しているあいだは画面の配色を変え、自分の情報と取り違えないようにした。
- 見守り画面の「見守っている／見守られている」家族の切り替えは、最初はプルダウンで作ったが、操作が分かりにくいため2つの大きなボタンに改めた。
- 切り替えのボタンは、最初は見守っている家族がいるときだけ表示していた。しかし、家族の画面を見たことがある人や、あとから見守りを始めた人にとっては、ボタンが出たり消えたりすると「いま誰の情報を見ているのか」が分かりにくくなる。そこで、見守っている家族がいない場合も「自分」のボタンだけは選択された状態で常に表示し、自分のお薬の情報を見ていることが一目で分かるようにした（`public/js/viewTarget.js` の `renderSwitcher`）。切り替える相手がいないので、押しても表示は変わらない。

## 8. 招待コードを書き写しやすくした
- 関連: `0006_regenerate_invite_code.sql`、`src/routes/careGroups.js`
- 招待コードは、電話や紙で家族に伝えることも想定される。以前は16進数（0〜9 と a〜f）の小文字だった。
- 見間違えやすい文字（0 と O、1 と I と L）を使わない、英大文字と数字の8文字にした。
- 入力するときは大文字・小文字を区別せず、書き写したときに入りやすい空白やハイフンも無視するようにした（入力欄は最初から大文字になるようにした）。
- 区別しないことを入力欄の上に「英字は大文字・小文字のどちらで入力しても大丈夫です。」と書いた。書いておかないと、利用者は大文字・小文字を気にして入力に時間がかかったり、小文字で打ったものを消して打ち直したりしてしまう。システムが受け入れる入力の幅は、画面で伝えて初めて利用者の負担を減らせる。
- 文字の種類を31種類に絞っても、8文字で約8,500億通りあり、当て推量で他人のコードを当てるのは現実的でない。

## 9. 登録画面の「使い方」を、基本機能と追加機能に分けて問うようにした
- 関連: `public/signup.html`
- 以前は「どのように使いますか」という問いに、「家族に見守ってもらう」「自分のお薬の管理だけ」「家族を見守る」の3つを同列に並べていた。
- しかし、お薬の記録はどれを選んでも使える基本機能であり、見守りの2つは追加の機能である。「〜だけ」という言い方のせいで、他を選ぶとお薬の管理が含まれない（制限される）ように読めてしまっていた。説明文にも「ご自分のお薬の記録もできます」が書かれている選択肢と書かれていない選択肢があり、揃っていなかった。
- そこで、選択肢の上に「お薬の記録・服薬のアラームは、どれを選んでもお使いいただけます。」と共通の前置きを1か所だけ置き、問いを「ご家族とどのように使いますか」に絞った。
- 「自分のお薬の管理だけ」は「今は家族とつながらない」と言い換え、何も足さない選択肢として最後に置いた。「見守りはあとからマイページで始められます」と添え、選んでも後戻りできることを伝えた。
- 選択肢の中身（保存される設定）は変えず、文言と並び順だけを直した。

## 新規登録の「使い方」の選択肢を、選んだものがひと目で分かる形にした

- もとは本物のラジオボタンを隠し、選んだカードの枠の色と、ごく薄い背景色だけで選択中を示していた。色の差が小さく、高齢の方には「どれを選んでいるか」が分かりにくかった。
- 選択中を色の違いだけに頼らず、次の3つを重ねて示すようにした。
  - カードの左に大きな丸印を置き、選ぶと藍色に塗られて「✓」が付く（形の変化）。
  - 選んだカードの背景をはっきりした薄い藍色にし、枠を太くする（面積の大きい変化）。
  - 「選択中」という文字の札を出す（文字による明示）。
- 色覚に特性のある方や、画面が見えにくい方でも、形と文字で区別できる。丸印と札は `aria-hidden` にして、読み上げは従来どおりラジオボタンの選択状態で伝わるようにした（読み上げが二重にならない）。
- 見出しの文字を大きく（24px）し、説明文も補助色のままでは薄いため、選んだカードでは本文色に濃くした。

## 「あとで変えられる」という案内を、選ぶ前に・対象をはっきりさせて示した

- もとは選択肢の一番下に「あとから「マイページ」で変更できます。」とだけ書いていた。主語がなく、下に続くお名前やメールアドレスの欄のことにも読めた。また、選び終わってから目に入る位置だった。
- 「あとで変えられる」は、選ぶ前に知っていれば迷わずに済む情報なので、選択肢の上の前置きに移した。高齢の方が「間違えたら取り返しがつかない」と悩んで手が止まるのを防ぐねらい。
- 文言は「ここで選んだ使い方は、あとからマイページの「使う機能」で変えられます。」とし、何を（使い方）・どこで（マイページの「使う機能」）変えられるかを、実際の見出し名まで書いた。あとで探すときの手がかりになる。
- マイページでは「見守る」「見守ってもらう」を両方選べるが、登録画面では1つしか選べない。この食い違いで両方使いたい人が迷わないよう、「両方使いたい方も、まずはどちらか1つを選んでください。」と添えた。
- 「今は家族とつながらない」の説明に入っていた同じ趣旨の一文（見守りはあとからマイページで始められます）は削り、案内を1か所にまとめた。


## 重なって開いた画面の上にも、お知らせ（トースト）を出す
- 関連: `public/js/ui.js`（`showToast` / `placeToastArea`）
- 問題: お薬の編集画面などは `<dialog>` の `showModal()` で開いている。この方法で開いた画面はブラウザの「最前面の層（トップレイヤー）」に表示されるため、ページ側に置いたトーストは `z-index` をいくら大きくしても裏に隠れてしまう。同じ時刻の服薬スケジュールを2つ入れて保存したときのエラーが、編集画面の裏に出て読めなかったことで気づいた。
- 工夫:
  - モーダルを開いているあいだは、トーストの置き場所をそのモーダルの中に移すようにした。トーストを出す共通の関数を1か所直すだけで、すべての画面に効く。
  - モーダルを閉じたときは置き場所を元に戻し、「登録しました。」のように、閉じる直前に出したお知らせが一緒に消えないようにした。
  - トーストを最前面に出す別の方法として Popover API もあるが、iPhone では iOS 17 以降でないと使えない。古い端末を使う高齢者もいることを考え、採用しなかった。
  - エラーのトーストは、読み終わる前に消えないよう、表示時間を約3秒から約6秒に延ばした。成功のお知らせは短いままにした。
- 画面の中にエラー文を出す方法（入力欄のそばに表示する）も検討した。しかし、重なっている行にはすでに赤茶色の枠を付けていて、どこを直せばよいかは分かる。トーストと同じ内容を2か所に出すと、かえって分かりにくくなるため、採用しなかった。

## 記録画面の日付の欄を、スマートフォンでも「押して選ぶ欄」と分かるようにした
- 関連: `public/logs.html`、`public/css/logs.css`（`.date-picker` / `.date-placeholder`）、`public/js/pages/logs.js`
- 問題: 日付の絞り込みには `<input type="date">` を使っている。パソコンのブラウザでは未選択でも「年/月/日 📅」と表示されるが、スマートフォン（特に iPhone の Safari）では未選択の欄が何も書かれていない空白になり、日付を選べる欄だと気づきにくかった。日付の入力欄には `placeholder` 属性が効かないため、ブラウザの機能だけでは案内を出せない。
- 工夫:
  - 日付を選んでいないあいだだけ、欄の上に「📅 日付を選ぶ」という案内を重ねて表示するようにした。案内は `pointer-events: none` にして、押すと下の日付欄がそのまま反応するようにした。
  - 案内を重ねるとパソコンでは📅のボタンが隠れるため、欄のどこを押してもカレンダーが開くようにした（`showPicker()`。使えない古いブラウザでは標準の動きに任せる）。
  - 「日付」「状態」の見出しを欄の上に付け、何を絞り込む欄なのかを言葉でも示した。
  - 端末ごとに表示が変わらないよう、パソコンとスマートフォンで同じ案内を出すことにした。

## アプリのアイコンを「お薬」と「時間・見守り」が一目で分かる図柄にした
- 関連: `scripts/generate-icons.ps1`、`public/assets/`（`icon-192.png` / `icon-512.png` / `icon-maskable-512.png` / `apple-touch-icon.png` / `favicon-32.png` / `badge-96.png`）、`public/manifest.json`、`public/sw.js`、`mobile/android/app/src/main/res/mipmap-*/`
- 問題: もとのアイコンは藍色の地に白い円を描いただけで、何のアプリか分からなかった。Android アプリは Capacitor の初期アイコンのままだった。高齢の方はスマホのホーム画面でアプリを「絵」で探すことが多く、ほかのアプリと見分けにくいと、お薬の時間にすぐ開けない。
- 工夫:
  - 図柄は「時計の文字盤」の上に「カプセル」を重ねたものにした。カプセルで「お薬のアプリ」、文字盤で「決まった時間に飲む・アラームで知らせる・家族が見守る（watch）」ことを表し、アプリ名 medi-watch の意味を1枚で伝えるようにした。
  - 色は画面と同じ藍色・紙色・テラコッタ橙だけを使い、アプリを開く前と後で印象がそろうようにした。
  - 小さく表示されても形が分かるよう、文字盤の目盛りは 12・3・6・9 時の4本だけにし、細かい針や文字は入れなかった（32px のファビコンでもカプセルと分かる）。
  - Android の端末やランチャーはアイコンを丸・角丸・しずく形などに切り抜く。切り抜かれても欠けないよう、PWA 用には全面を塗った「maskable」アイコン（図柄は中央 80% に収める）を、Android アプリ用には前景と背景色を分けた「アダプティブアイコン」（図柄は中央 66dp に収める）を用意した。
  - Android の通知のステータスバーに出る「バッジ」は、画像の透明でない部分だけを白く塗って表示される。もとは通常のアイコンをそのまま使っていたため白い四角になっていたので、白いカプセルの形だけを透明の地に描いた専用の画像にした。
  - アイコンは画像編集ソフトで描かず、図形の座標を書いたスクリプトから全サイズ（Web 版6種類・Android 版15枚）を作るようにした。Windows 標準の機能（System.Drawing）だけで動くので、Node や Python が入っていない学校のパソコンでも作り直せる。色や大きさを変えても、全サイズの見た目がずれない。

## ネイティブ版の全画面アラームに、上部の通知が重ならないようにした（2026-11-16）
- スマホの操作中にお薬の時間になると、全画面の「お薬の時間です」の上に、画面上部の通知（ヘッズアップ通知）が重なって残り、時刻や「カメラを起動する」ボタンの一部を隠していた。高齢の利用者には、どちらを押せばよいか迷う原因にもなる。
- 原因は、ロック中・画面が消えているときに全画面を出すための「全画面インテント」付きの通知が、操作中は全画面ではなく上部の通知として出る仕組みにあった。アプリは「ほかのアプリの上に重ねて表示」の許可で全画面を自分で開いていたため、両方が同時に出ていた。
- そこで、通知のチャンネル（重要度）を2つ用意し、状況で出し分けるようにした。
  - 全画面が見えているあいだ … 重要度「低」で、全画面インテントを付けない通知にする。通知欄には残るが、画面上部には出ない。
  - 画面が消えている・ロック中・全画面を離れたとき … これまでどおり重要度「高」＋全画面インテントの通知にする。
- 「見えているかどうか」は全画面の画面（AlarmActivity）の onStart／onStop で判断し、ホームボタンなどで離れたときは上部の通知に戻して、鳴っている理由に気付けるようにした。全画面を開いたつもりでも機種の制限などで開かなかった場合に備え、3秒後に見えていなければ上部の通知に出し直す保険も入れた。
- あわせて、アラームの画面ではステータスバー（時計・電池など）を隠し、画面いっぱいに時刻とボタンを表示するようにした。下の「戻る・ホーム」のバーは、操作に迷わないよう隠していない。

## アラームの画面に「いまの時刻」を足し、予定の時刻と見分けられるようにした（2026-11-17）
- 関連: `mobile/android/app/src/main/java/jp/mediwatch/app/alarm/AlarmActivity.java`、`public/js/alarm.js`、`public/css/base.css`
- きっかけ: ネイティブ版を使った人から、「お薬の時間に出る画面の時刻は飲む予定の時刻だが、実際の時刻も書くべきではないか」という意見が出た。
- 問題: 画面には「08:00」と数字だけを大きく出していた。作った側は「予定の時刻」のつもりでも、説明のない大きな数字は「いまの時刻」と読まれやすい。しかも、「あとで」を押した5分後、記録しないままの鳴らし直し、電源を入れ直したあとの鳴らし直しでは、表示は「08:00」のまま、実際は 08:20 ということが起こる。ネイティブ版のアラームの画面はステータスバー（端末の時計）を隠しているので、いまの時刻を確かめる手がかりも無かった。
- 工夫:
  - いまの時刻を「いまの時刻 08:20」と言葉を添えて、画面の一番上に小さめに出した。時刻を2つ並べるだけでは、かえってどちらが何の時刻か迷うため、数字だけでは出さない。
  - 予定の時刻は「08:00 の／お薬の時間です」と文の中に入れた。「予定の時刻」という見出しを足すのではなく、もとからある「お薬の時間です」とつなげて読める形にしたので、画面の文字は「の」の1文字しか増えていない。
  - 主役（大きい文字）は予定の時刻とお薬の名前のままにし、いまの時刻は補足の大きさにとどめた。知らせたいのは「どのお薬を飲むか」であり、時計ではないためである。
  - ネイティブ版は Android の `TextClock` を使い、分が変わると自動で進むようにした。端末の設定が12時間制でも、予定の時刻と同じ24時間制で出し、2つの時刻を見比べやすくした。
  - アプリを開いているときに出る画面（Web 版・ネイティブ版共通）も同じ並びにそろえ、どちらの画面でも同じ読み方ができるようにした。
- 遅れが分かることで、「食後のお薬なのに、もう時間が経っている」といったことに利用者が自分で気づける。
- 数字は、作った側には意味が自明でも、利用者には「何の数字か」が伝わらないことがある。時刻・回数・量などを画面に出すときは、何を表す数字かを言葉で添える必要がある。

## アラームの画面から、飾りのベルの印を外した（2026-11-17）
- きっかけ: ネイティブ版のアラームを実際に鳴らして見た開発者から、「ベルの印があるせいで、文字やボタンが小さくなる」という意見が出た。
- それまでの画面: いちばん上に、テラコッタ色の丸の中で揺れるベルの印（96dp）を置いていた。「アラームらしさ」を出すための飾りで、Web 版の画面と同じ形・同じ動きにそろえてあった。
- 判断: 外した。理由は次の3つ。
  - ベルが伝えること（「知らせが来ている」）は、「お薬の時間です」の文字、アラームの音、読み上げ、振動ですでに伝わっている。ベルが無くても、利用者が受け取る情報は減らない。
  - ネイティブ版では「カメラを起動する」が画面の残りの高さをすべて使う。ベルと余白の分（約110dp。一般的なスマホの画面の高さの1割強）が、そのままいちばん押してほしいボタンの大きさになる。
  - 揺れ続ける印は目を引く。目を引いてほしいのは、押すボタンと、飲むお薬の名前のほうである。
- Web 版（アプリを開いているときの画面）からも同時に外した。ネイティブ版では、端末のアラームのあとに Web の画面のアラームが続けて出るので、片方にだけベルがあると、別のお知らせに見えてしまうためである。
- 「あったほうが、それらしく見える」部品でも、画面の高さが限られるスマホでは、押すボタンや読む文字を小さくしてしまう。高齢の利用者に向けた画面では、「その部品が無いと何が伝わらなくなるか」を考え、何も減らないなら外す、という基準で選んだ。

## アラームの音量をいちばん下まで下げても、小さく鳴るままにした（2026-11-17）
- きっかけ: ネイティブ版で、アラームの音量をいちばん下まで下げても音が鳴ることに開発者が気付き、「鳴らないようにするべきか、少しは鳴るほうがよいか」を検討した。
- 分かったこと: これはアプリが音量を上げているのではない。Android（9 以降の多くの機種）は、「アラーム」の音量だけ、いちばん下でも0にならないように作られている（着信音やメディアの音量は0にできる）。アプリは、その「アラーム」の音量でそのまま鳴らしている。
- 判断: そのままにした（いちばん下でも小さく鳴る）。
  - 高齢の利用者では、「わざと0にした」よりも「知らないうちに下げてしまった」ことのほうが起こりやすい。まったく鳴らないと、下げたことに本人が気付く機会がなくなり、飲み忘れが続く。
  - 鳴ってしまう害（小さな音が鳴る）より、鳴らない害（お薬を飲み忘れる）のほうが大きい。
  - 音を止めたいときの方法は、別に用意してある（「あとで」を押す・記録する）。音量を0にすることを「止める手段」にする必要がない。
  - アプリの側で「いちばん下なら鳴らさない」と作り込むと、スマホに初めから入っている時計のアラームと違う動きになり、かえって分かりにくい。
- 反対に、アプリが音量を勝手に上げることもしていない。利用者が決めた音量を、アプリが黙って変えるべきではないと考えた。

## アラームの画面の長い案内文を、ボタンと短い1行に置き換えた（2026-11-17）
- きっかけ: ネイティブ版のアラームの画面には、「映像なしで記録するときや、スキップするときは、「カメラを起動する」を押すと出る画面から選べます。」という案内文があった。開発者から「分かりにくい。その場所にボタンを置くほうがよいのではないか。ただし「カメラを起動する」を圧迫するのが心配」という意見が出た。
- 問題: この文は、2つの用事（映像なしで記録する・スキップする）の行き先を、1つの長い文で説明していた。映像を残したくない人は、文を読んで理解したうえで、使いたくない「カメラを起動する」を押す必要があった。
- 判断: 2つの用事を、よく使うかどうか・押し間違えたときの害で分けた。
  - 「映像なしで記録する」は、ボタンにした。毎回これを選ぶ人がいる用事であり、アプリの中のアラーム（Web の画面）にはもとから同じボタンがある。並びも「カメラ → 映像なし → あとで」で同じになった。
  - 「スキップする」は、ボタンにしなかった。使うことが少なく、押すと家族に「飲み忘れの可能性」と通知が届く。ロック中にも出る画面で、1回押しただけでそうなるのは避けた。「いまは飲めない」は「あとで」で足りる。
  - 代わりに、「飲まないときは、「カメラを起動する」の先で選べます。」という短い1行だけを残した。案内文をすべて消すと、スキップがどこにあるかの手がかりが画面から無くなるためである。
- 「カメラを起動する」を圧迫する心配について: 同じ日にベルの印（約110dp）を外し、案内文を3行ほどから2行ほどに短くした。空いた高さのほうが、足したボタン1つ分（約80dp）より大きいので、「カメラを起動する」は、これらの変更の前より大きいままである（数値は概算）。部品を足すときは、先に「外せる部品」を探すと、いちばん大事なボタンを小さくせずに済む。
- お薬が2つ以上あるとき: 端末のアラームの画面では、まとめて記録しない。ボタンを押すとアプリが開き、アプリの中の画面で、飲んだお薬を1つずつ選ぶ。飲んでいないお薬まで「飲んだ」になるのを防ぐためで、アプリの中のアラームと同じ考え方である。
- 「説明文で行き先を教える」より「その場にボタンを置く」ほうが、読む量も押す回数も減る。ただし、すべてをボタンにすると、押し間違いの害が大きい操作まで手前に出てしまう。よく使う操作はボタンに、害の大きい操作は1つ先の画面に、と分けた。

## アラームの画面で、お薬の名前を枠で囲み、「あとで」も枠のあるボタンにした（2026-11-17）
- きっかけ: ネイティブ版のアラームを実機で見た開発者から、「「12:28 の お薬の時間です」とお薬の名前の色がほとんど同じで見づらい」「「あとで」も四角で囲ってほしい」という意見が出た。
- 問題:
  - 見出しは藍色（#1D3338）、お薬の名前は墨色（#33312E）で、配色の決まりの上では別の色だが、どちらも黒に近く、画面では同じ色に見える。色の名前が違っていても、明るさが近ければ見分けられない。
  - 「あとで」は、目立たせないために枠も地の色も無いボタンにしていた。その結果、ただの文に見え、押せる場所だと分かりにくかった。
- 工夫:
  - お薬の名前は、文字の色を変えるのではなく、白い地にテラコッタ色の枠で囲んだ。文字を橙などの明るい色にすると、紙色の背景との明るさの差（コントラスト比）が約12:1 から約4:1 に下がり、高齢の利用者にはかえって読みにくくなる。文字は濃い色のまま、地と枠で「ここがお薬の名前」と分けた。
  - 枠の色は、アプリの中のアラームで、お薬が複数あるときに使っている「お薬ごとの枠」と同じにした。「テラコッタ色の枠の中がお薬」という見え方を、どの画面でもそろえるためである。
  - 「あとで」は灰色の枠で囲んだ。「カメラを起動する」（塗りつぶし）＞「映像なし」（藍色の枠）＞「あとで」（灰色の枠）と、押してほしい順に目立つようにし、枠を付けても順番が崩れないようにした。
  - アプリを開いているときに出る画面（Web 版・ネイティブ版共通）も、同じ見た目に変えた。
- 「目立たせない」ことと「押せると分からない」ことは別である。控えめにしたい操作でも、押せる場所であることは形（枠）で示し、目立ち方は色の濃さで調整する、と分けて考えた。

## アプリの中のアラームの読み上げを、音量ボタンで調整できるようにした（2026-11-17）
- きっかけ: ネイティブ版で、端末のアラームの「映像なしで「飲んだ」を記録」からアプリの中の「お薬の時間です」の画面に移ると、小さな声で読み上げが聞こえるが、音量ボタンを押しても大きさが変わらない、という意見が開発者から出た。「調整できるようにするか、ここでは音を出さないようにするか」を検討した。
- 原因（ソースコードから分かること）: 読み上げは「アラーム」の音量で鳴らしている。一方、アプリの画面で音量ボタンを押すと、Android の決まりで「メディア」の音量が変わる。つまり、利用者が動かしているつまみと、鳴っている音のつまみが別だった。端末のアラームの画面のほうは、もとから音量ボタンを「アラーム」の音量に向けてあった。
- 判断: 音を消すのではなく、読み上げているあいだだけ、音量ボタンで「アラーム」の音量を変えられるようにした。
  - 読み上げには役割がある。同じ時刻のお薬の1つ目を記録したあと、「まだ□□が残っている」ことを声で知らせる場面で使っている。消すと、画面を見ていない利用者に残りのお薬が伝わらなくなる。
  - 困っていたのは「音が鳴ること」ではなく「大きさを変えられないこと」である。変えられるようにすれば、小さくしたい人も大きくしたい人も自分で決められる。
  - 見た目が同じ2つの画面（端末のアラーム・アプリの中のアラーム）で、音量ボタンの働きが違うと、利用者は「さっきは変えられたのに」と迷う。
  - 読み上げが終わったら、音量ボタンはいつもの音量（記録の映像を見るときなどの「メディア」）に戻す。ずっと「アラーム」のままにすると、映像の音を調整できなくなるためである。
- 利用者が「押しても何も変わらない」と感じる操作は、機能が無いことよりも不安を与える。音を出すなら、その音を利用者が調整できる手段を、同じ画面の中にそろえておく必要がある。

## アラームの予定の時刻を「08:00 の」から「08:00 に飲む」に変えた（2026-11-17）
- きっかけ: 開発者から、「13:12 のお薬の時間です」より「13:12 に予約されたお薬の時間です」のほうが分かりやすいのではないか、という意見が出た。
- 問題: 「の」の1文字では、大きな時刻が「いまの時刻」なのか「飲む予定の時刻」なのかが、まだ伝わりにくかった。上に「いまの時刻 13:20」も出ているので、時刻が2つ並ぶ。
- 判断: 意見の狙い（予定の時刻だとはっきりさせる）は取り入れた。ただし、言葉は「予約された」ではなく「に飲む」にした。
  - アプリのほかの画面では、この時刻を「予約」と呼んでいない（お薬の登録画面は「服薬スケジュール」「+ 時間を追加」）。アラームの画面でだけ別の言葉を使うと、同じものだと結び付かない。
  - 高齢の利用者にとって「予約」は、病院や薬局の予約を思い起こさせやすい。「病院の予約の時間？」と取り違えるおそれがある。
  - 「予約された」は、アプリが時刻を決めたように読める受け身の言い方で、利用者がすること（飲む）が書かれていない。「13:12 に飲む／お薬の時間です」なら、何時に何をするかが1文で分かる。
  - 文字数も少ない（「に予約された」6文字に対し「に飲む」3文字）。時刻と同じ行に半分の大きさで並べており、長いと狭い画面で行が折り返して、時刻が読みにくくなる。
- 画面の言葉は、作る側の言い方（予約・スケジュール）ではなく、利用者がすること（飲む）で書くと伝わりやすい。また、同じものはアプリ全体で同じ言葉で呼ぶ必要がある。
