# 服薬記録と通知の正確さの工夫

## 1. 日付・時刻をすべて日本時間（JST）で扱う
- 関連コミット: `3ea7210`（`src/lib/jst.js` を追加）
- 問題: 本番のサーバー（Render）は UTC で動いているため、`new Date()` の日付・時刻をそのまま使うと9時間ずれる。例えば 8:00 の予定が 17:00 に通知されたり、朝 0〜9 時の予定が前日の扱いになったりする。
- 工夫: 日本時間の今日の日付・曜日を求める関数（`jstToday`）と、「日付＋服薬時刻」を日本時間として解釈する関数（`buildScheduledAt`）を1か所にまとめ、cron・API の両方で使うようにした。

## 2. サーバーのスリープや処理の遅れがあっても通知を取りこぼさない
- 関連: `src/services/reminderCron.js`
- 問題: 「リマインド時刻の前後30秒以内」だけを送信対象にすると、無料サーバーのスリープや cron の遅れで1分飛んだだけで、その通知は永久に送られなくなる。
- 工夫: 「リマインド時刻を過ぎていて、服薬時刻＋30分より前で、まだ送っていないもの」を対象にした。家族への「飲み忘れ」通知は `notification_logs` に送信済みを記録して、二重に送らないようにした。

## 3. 予定の時刻より前に「飲んだ」を押しても、正しく服薬済みになる
- 関連コミット: `3ea7210`
- 問題: 以前は「飲んだ」を押した時刻で記録を作っていたため、cron が作る本来の予定の記録とは別物になり、本来の予定が「未記録」のまま残っていた（その後、家族に飲み忘れ通知が届いてしまう）。
- 工夫: 記録の予定時刻は、押した時刻ではなく「日付＋スケジュールの服薬時刻」からサーバーが決めるようにした。同じ予定の記録がすでにあれば新しく作らずにそれを使うので、記録が二重にできない。

## 4. お薬を削除しても、過去の記録は残す
- 関連コミット: `b8ffb51`
- 問題: お薬の行を削除すると、データベースの `ON DELETE CASCADE` により、スケジュール経由で過去の服薬記録まで消えてしまう。お薬手帳として、過去の履歴が消えるのは問題になる。
- 工夫: 行は削除せず「停止（`is_active = false`）」にした。消すのは「これからの未記録」だけにして、服薬済み・スキップ・飲み忘れの記録は履歴として残す。停止したお薬の記録には通知も送らない。

## 5. お薬の時刻を変えた日の扱いを細かく決めた
- 関連コミット: `c8ae8ea`, `6cef03d`, `cb7a9ff`, `e77d61c`（`src/lib/scheduleLogs.js`）
- 時刻を変えたときに起こりうる問題を一つずつ洗い出して対応した。
  - 時刻を変えたら、その日の予定をすぐ新しい時刻で作り直す（cron を待たずに記録タブへ反映）。
  - 変更前の時刻ですでに「飲み忘れ」になっていた記録は消さずに残す（履歴を改ざんしない）。
  - その日すでに服薬済み・スキップなら、新しい時刻の予定は作らない（同じ日に2回飲ませないため）。
  - 時刻を今より前に変えた日は、その予定をホームに出さない。
  - 変更前の時刻の記録には、リマインドや家族への飲み忘れ通知を送らない（例: 8:10 に 8:00 の予定を 20:00 へ変えたのに、8:30 に家族へ「飲み忘れ」が届くのを防ぐ）。

## 6. 1台の端末には、最後にログインした1人の通知だけを届ける
- 関連コミット: `1a68308`, `ca476dd`, `76bab28`（`public/js/push.js`, `src/routes/push.js`）
- 問題: ブラウザのプッシュ購読は端末（ブラウザ）ごとに1つで、アカウントとは関係なく残る。家族で1台のスマホを共有し、別のアカウントでログインし直すと、前の人あての服薬リマインドが届き続けてしまう。
- 工夫:
  - 端末を登録するとき、同じ端末に結び付いた別の利用者の登録を削除する（他人の行は RLS で消せないので、この処理だけ管理者権限を使う）。
  - 画面を開くたびに、端末を「いまログインしている人」に結び付け直す。
  - ログアウト時には、その端末と利用者の結び付きをサーバーから消す。
- 通知の設定に失敗したとき、どの段階（Service Worker の登録／公開鍵の取得／購読／サーバー登録）で失敗したかを画面に出すようにし、原因を切り分けやすくした。
- cron を待たずに自分の端末へテスト通知を送れる API（`POST /api/push/test`）を用意し、本番環境で通知を確かめやすくした。

## 7. アクセストークンの更新を1回にまとめる
- 関連: `public/js/api.js`（`refreshSession`）
- 画面を開いたときに複数のAPIを同時に呼ぶと、トークンの期限切れでそれぞれが更新処理を始め、使い捨てのリフレッシュトークンを使い切ってログアウトされてしまう恐れがある。更新処理は1つだけ実行し、ほかのリクエストはその結果を待って共有するようにした。

## 8. 記録タブから、付け忘れの登録と記録の訂正ができる
- 関連: `PATCH /api/logs/:id/status`（`src/routes/logs.js`）、`public/js/pages/logs.js`
- 問題: これまで記録はホーム画面の「今日の予定」からしか付けられなかった。翌日に「昨日は飲んだのにボタンを押し忘れた」と気付いても直せず、押し間違えた「スキップ」も戻せなかった。また、無料サーバーのスリープで cron が動かなかった日は、記録そのものが作られていないことがある。
- 工夫:
  - 記録の状態は「服薬済み」「スキップ」「取り消し（未記録に戻す）」の3つから選ぶ。「飲み忘れ」はデータとしては持たず、「未記録のまま予定時刻を過ぎたもの」として画面で判断している。そのため、取り消したときは予定時刻を過ぎていれば自動的に「飲み忘れ」と表示され、状態が食い違わない。
  - 記録の追加は、cron と同じ「日付＋服薬時刻」で予定時刻を決める既存の API（`POST /api/logs`）を使う。同じ予定の記録がすでにあればそれを更新するので、二重に記録されない。明日以降の日付はサーバー側でも受け付けない。
  - 選べるお薬は、選んだ日の曜日に飲む予定のものだけに絞った。
  - 日付はカレンダー（`input type="date"`）ではなく、「今日」「昨日」…と30日前までを並べた選択肢から選ぶ形にした。カレンダーでは明日以降の日付を画面から消せず（Chrome は灰色で表示するだけ、iPhone の Safari は選べる日の上限 `max` にも従わない）、高齢の利用者が未来の日付を押してしまう恐れがあるため。
  - 記録の一覧は、最初は「記録した時刻」で並べ、記録した日ごとにまとめていた。しかしこれでは、昨日の分を今日直すと、その記録が「今日」のまとまりに移ってしまい、どの日の分か分かりにくかった。そこで並び順とまとまりを「予定時刻」に統一し、記録した時刻は「記録：○月○日 ○:○○」として小さく添える形にした。状態を変えても記録の位置が動かず、上部の日付の絞り込み（予定の日付で絞り込む）とも一致する。
  - 家族への通知は、今日の予定を変えたときだけ送る。過去の日を訂正したときに「服薬完了」が届くと、家族が「いま飲んだ」と誤解するため。
  - 「服薬済み」以外に変えても服薬映像は消さない。押し間違いを戻せば、映像もまた見られる。
  - 変更は本人だけが行える（サーバーで本人の記録かを確かめ、RLS でも家族は参照だけに限っている）。
- ホーム画面は別のページなので、開くたびに最新の記録を読み込む。ブラウザの「戻る」で前の画面がそのまま復元された場合（bfcache）にも読み直すようにし、記録タブで変えた内容がホームに必ず反映されるようにした。
