# お薬手帳QRコード（JAHIS形式）の読み取りで工夫したこと

## 実物のQRコードを読み取って、その中身に合わせてパーサーを作り直した
- 最初は仕様書から推測した項目の並び（レコード番号「21」に薬品名・用法・用量が1行で並ぶ）で解析していたが、実際の医院の明細書のQRコードは読み取れても「医薬品情報が含まれていません」となった。
- 開発者ツールのコンソールに読み取った内容を一時的に出して確かめたところ、実データ（JAHISTC06）では薬の情報が次の3種類の行に分かれていた。
  - `201`（薬品）: RP番号・薬品名称・用量・単位
  - `301`（用法）: RP番号・用法名称・調剤数量（例: 24）・調剤単位（例: 日分）
  - `311`（用法補足）: RP番号・補足の説明
- 薬と飲み方は「RP番号」でつながっている（同じ飲み方の薬のまとまり）。そこで、用法・補足を先に RP番号ごとに集め、同じ RP の薬それぞれにメモとして付けるようにした。1つの RP に薬が複数あっても、すべての薬に同じ飲み方が付く。
- 患者名・生年月日・住所・医療機関・医師などの行（`1`, `11`, `15`, `51`, `55` など）は個人情報なので、アプリでは読まないようにした。
- 確認用のログは、パーサーの調整が終わった時点で削除した。本番のサイトで動作を確かめる運用なので、個人情報を含む内容がコンソールに出続けないようにするため。

## 利用者に分かりやすい形にそろえた
- QRコードの中の文字は全角英数字（「１０ｍｇ」「ｇ」）で書かれているため、Unicode の NFKC 正規化で半角にそろえた。読みやすくなるだけでなく、単位「ｇ」がアプリの単位の選択肢「g」と一致し、プルダウンで自動的に選ばれるようになった。
- 塗り薬の調剤数量「1調剤」は高齢の利用者には意味が分かりにくいので、メモには「◯日分」「◯回分」のときだけ載せるようにした。
- 確認画面にメモの欄を加え、読み取った飲み方を登録前に確認・修正できるようにした。

## 関連（Shift_JIS への対応）
- JAHIS形式のQRコードは日本語が Shift_JIS で書かれている。jsQR は UTF-8 として読めないと文字列を空にしてしまうため、元のバイト列から `TextDecoder` で UTF-8 → Shift_JIS の順に試して文字に戻している。
