# アカウント削除後に端末のアラームを確実に止める工夫

## 背景
- ネイティブ版（Android）の服薬アラームは、通信できなくても鳴るよう、予定を端末に保存して端末だけで鳴らしている。
- 開発中に SQL でアカウントを消したところ、消したアカウントのお薬のアラームが、触れない場所に置いたスマホで鳴り続けた（考察のメモ「端末だけで鳴らすアラームとアカウントの削除」を参照）。

## 工夫したこと
1. **「消し方」を問わず止まるよう、3つの機会で気づく**
   - 鳴らす前：端末がサーバーへ「このアカウントはまだあるか」を確かめ、削除されていれば鳴らさずに予定を消す（`AlarmAccount.ringUnlessDeleted`）。SQL やダッシュボードで直接消した場合も止まる。
   - アプリを開いたとき：同じ確認を裏で行う（`MainActivity.onStart`）。
   - アプリの「アカウントを削除する」で消したとき：サーバーが、削除の直後にその人の端末へ FCM のデータメッセージを送り、アプリを閉じていても、その場でアラームを止める（`AccountMessagingService`）。
2. **止めるのは「削除された」とはっきり分かったときだけ**
   - サーバーは、アカウントが無いときだけ 410 と `ACCOUNT_DELETED` を返す。端末は、通信できない・サーバーの障害・中継の機器が返した 410 など、ほかの答えではすべて「いつもどおり鳴らす」。電波が無いだけで飲み忘れにつながらないようにした。
   - ログインの期限切れでは止めない（次の 3. の鍵を使うため、期限切れとアカウントの削除を区別できる）。
3. **ログインのトークンとは別の「アラーム用の鍵」**
   - 端末が確かめるときは、ログインのトークン（1時間で切れ、使うたびに入れ替わる）ではなく、サーバーが署名したアラーム用の鍵を使う（`src/lib/alarmKey.js`）。
   - 鍵は DB に保存せず、サーバーだけが知る値からの署名で正しさを確かめる。そのため、テーブルの追加（マイグレーション）が要らない。
   - この鍵でできるのは「アカウントがあるか」を確かめることだけで、お薬などの情報は読めない。鍵を盗まれても、個人情報は漏れない。
4. **時刻どおりに鳴らすことを崩さない**
   - 答えを待つのは最長4秒にした。Android では、予約したアラームから音を鳴らすサービスを始められるのは時刻から10秒ほどのあいだだけのため。また、Render のサーバーは眠っていると答えに1分近くかかるため。
   - 4秒を過ぎたら鳴らし始め、あとで「削除」と分かった時点で止める。
5. **別のアカウントの予定を誤って消さない**
   - 鍵と一緒に、その予定が誰のものか（ユーザー ID）を端末に保存する。削除の知らせが別のアカウントのものなら消さない。
   - 確かめているあいだに別のアカウントでログインし直した場合も、新しいアカウントの予定は消さない。
6. **削除は決まった手順で、後始末の順番を守る**
   - FCM の宛先の読み出し → 映像の削除 → アカウントの削除（ほかのデータは CASCADE）→ 端末への知らせ、の順にした。宛先はアカウントと一緒に消えるため先に読み、端末への知らせは削除が済んでから送る。
   - パスワードの再入力で本人確認をする。違うときは 401 ではなく 403 を返す。401 だと画面が「ログイン切れ」と見なして、ログイン画面へ移ってしまうため。
