# Web版とネイティブ版で画面とサーバーを共有する工夫

## 背景
- Web アプリ（PWA）では、アプリを閉じているとき・ロック中・ほかのアプリを使っているときに、服薬アラームを鳴らせない（`卒論の考察として述べられること/Webアプリ（PWA）で服薬を知らせることの限界.md`）。
- 一方で、画面をすべてネイティブで作り直すと、Web 版と2つの画面を管理することになり、手間も不具合の元も倍になる。

## 工夫したこと
- **画面は1つ、届け方は2つ。** Capacitor を使い、Web 版の `public/` をそのまま Android アプリに同梱した。ネイティブで新しく作ったのは、アラームの部分（`mobile/android/app/src/main/java/jp/mediwatch/app/alarm/`）だけである。お薬の登録・記録・見守りなどの画面は、Web 版を直せばネイティブ版も直る。
- **画面をアプリに同梱する方式（Render の URL を開く方式にしなかった）。**
  - アラームから「カメラを起動する」を押したとき、画面はスマホの中から開くので、電波が弱くても、Render の無料プランがしばらく止まっていても、すぐ撮影画面が出る。
  - 同梱した画面はスマホの中（`https://localhost`）から開くため、サーバーとはオリジンが違う。そこで、`config.js` でアプリの中かどうかを判定して API の宛先を切り替え、サーバーには、アプリのオリジンだけを許可する CORS の設定を追加した（`server.js`）。認証は Cookie ではなく Authorization ヘッダーのトークンで行っているため、オリジンを許可しても、ほかのサイトから利用者になりすました操作はできない。
- **Web の画面とネイティブのアラームの役割分担。**
  - Web の画面（`alarm.js`）は、これまでどおりサーバーから予定と今日の記録を取得し、それを `NativeAlarm.sync()` で端末に渡す。端末側は予定を保存し、次に鳴らす時刻を1つだけ `AlarmManager.setAlarmClock` で予約する。
  - アプリを閉じていても鳴らせるよう、予定は端末に保存しておき、再起動後や時刻の変更後にも予約し直す（`BootReceiver`）。
  - 服薬時刻より前にアプリで記録した予定は、端末に「今日は済み」と伝えて鳴らさない。鳴っている最中に記録した場合も止める。
  - アラームの「カメラを起動する」は、Web 版のアラームと同じ入り口（`home.html?take=スケジュールID`）を開くようにした。撮影の処理を二重に作らずに済んだ。
  - ネイティブ版では音を端末のアラームが鳴らすので、Web の画面のアラームは音を出さないようにした（同時に鳴って聞き取りにくくなるのを防ぐ）。ただし通知が許可されていないときは、これまでどおり Web の画面で鳴らす。
- **サーバーの依存関係に影響させない。** ネイティブ版は `mobile/` に別の `package.json` を置き、Render が使うルートの `package.json` には Capacitor を入れていない。本番サーバーのビルドが重くなったり壊れたりしない。
- **高齢の利用者への配慮。** アラーム画面は、Web 版と同じ色（藍色・テラコッタ）で、「カメラを起動する」を画面の大部分を占める大きなボタンにした。戻るボタンでは閉じず、ボタンで選んでもらう。アラームに必要な4つの許可は、マイページに「済み ✓／設定する」の一覧で表示し、押すとその設定画面が直接開くようにした。

- **開発環境を別のパソコン・スマホで再現できるようにした。** 生成物（`node_modules/`、`npx cap sync` が `public/` からコピーする画面、Android Studio の個人設定など）は Git に入れず、ソースコードだけを管理している。その代わり、パソコンやスマホを変えたときに「どの手順をやり直す必要があるか」を `mobile/README.md` に表でまとめた。実際に作業して詰まった点（スマホが認識されない、Gradle と Java のバージョンが合わない）も、対処の手順として残した。署名用の鍵は作り直すと更新版を入れられなくなるため、作り直さずに引き継ぐことを明記した。さらに、作業を一時終了するときの手順（`mobile/開発を一時終了するときの手順.md`）もまとめた。アラームは端末に予約されるため、アプリや Android Studio を閉じても鳴り続ける。テスト用に登録したお薬を消し忘れると、毎日鳴ってしまう。この点を、終了時の確認項目に入れた。

## 卒論での書き方の例
- 「1つのコードから、インストール不要の Web 版と、確実に知らせる Android 版の2つを提供した。ネイティブで実装したのはアラームの部分（Java で約1,000行、コメントを含む）だけで、残りの画面・サーバー・データベースは共通である。」
