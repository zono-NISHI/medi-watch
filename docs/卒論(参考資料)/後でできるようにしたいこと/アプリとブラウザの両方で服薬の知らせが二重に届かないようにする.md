# アプリとブラウザの両方で服薬の知らせが二重に届かないようにする

開発中に次の手順を試したところ、通知を押すと、アプリではなくブラウザ（Chrome）で Web 版のログイン画面が開いた出来事から出た案（2026-11-26）。

1. ネイティブ版（Android）のアプリで、あるアカウントにログインした画面を開いておく
2. Supabase の SQL Editor でそのアカウントを削除する
3. アプリの画面がログイン画面に移る
4. そのアカウントで前に鳴ったアラームの通知（と思われるもの）を押す
5. ブラウザで Web 版のログイン画面が開く

## 現状（コードから分かること）
- ネイティブ版の端末のアラームが出す通知（`AlarmRinger` の鳴っているときの通知・「あとで」の通知、「カメラを起動する」）は、押すとどれも `AlarmActivity` か `MainActivity`（アプリ）を開く。ブラウザで URL を開く処理は Java にはない。
- アカウントの削除に気づいたときは、`AlarmAccount.forget()` が端末のアラームの通知を消す。
- ブラウザでログイン画面が開くのは、Web Push の通知（`public/sw.js` の `notificationclick`）を押したときだけ。リマインドの通知には `patientId` が無いので `home.html` を開き、アカウントが消えていれば 401 でログイン画面に移る。
- cron の「お薬の時間です」（`src/services/reminderCron.js`）は、その人の `kind = 'webpush'` の端末すべてに送る。ネイティブ版（`fcm`）には送らない（端末のアラームと二重になるため）。
- しかし、**同じ人が同じスマホの Chrome でも Web 版を開いて通知を許可していると、`webpush` の宛先が残り、お薬の時刻に「アプリのアラーム」と「Chrome の通知」の両方が届く**。どちらがどちらか、利用者には見分けにくい。
- アカウントを消すと `push_subscriptions` も消える（CASCADE）ので、新しい通知は届かなくなる。ただし、消す前に Chrome が受け取った通知は通知欄に残り、押すと上の 5. になる。
- 上の出来事で押した通知が本当に Chrome のものだったかは、実機ではまだ確かめていない（通知を長押しして「Chrome」かどうかを見れば分かる）。

## なぜ直すべきか
- **利用者を混乱させる**：同じお薬について知らせが2つ届くうえ、押すとアプリが開くこともブラウザが開くこともある。高齢の利用者は、ブラウザで開いた画面で「ログインし直して」と言われても、どうすればよいか分かりにくい。
- **二重に記録するおそれ**：アプリとブラウザの両方から同じお薬を記録しようとして、迷わせてしまう。
- アプリのアラームのほうが確実（通信できなくても鳴る、全画面で知らせる）なので、アプリを使う人にはアプリの知らせだけで十分。

## 「Chrome の通知からアプリを開く」ようにするのは勧めない
- Chrome の通知を押したときの動きは Chrome が決める。`clients.openWindow` は、Android App Links（`assetlinks.json` とアプリのインテントフィルター）を設定しても、ふつうは Chrome のタブで開き、確実にアプリへ移る方法はない。
- アカウントが消えたあとにログイン画面が出ること自体は正しい動き。直すべきなのは、開く先ではなく「二重に届くこと」のほう。

## 作り方の案
- **案A（アプリでログインしたら、ブラウザの知らせを止めるか尋ねる）**
  - ネイティブ版でログインし、端末のアラームを使い始めたとき、その人に `webpush` の宛先が残っていれば「このスマホのブラウザにも、お薬の時間のお知らせが届くようになっています。アプリのアラームだけにしますか？」と尋ねる。
  - 「はい」なら、その人の `webpush` の宛先をサーバーで消す（例：`DELETE /api/push/subscriptions?kind=webpush` のような API を足す）。
  - 課題：パソコンのブラウザなど、別の端末の Web Push まで消してしまう。どの端末か分かるよう、登録時に端末の種類（`user_agent` など）を保存して一覧で選べるようにするとよい。
- **案B（ネイティブ版の端末があれば、リマインドを Web Push に送らない）**
  - cron で、その人に `kind = 'fcm'` の宛先が1つでもあれば、`webpush` のリマインドを送らない。
  - 作るのは簡単だが、アプリを入れたスマホとは別にパソコンのブラウザで知らせを受けたい人には届かなくなる。家族への通知（`medication_missed` など）は対象外にする。
- **案C（Web 版で、アプリを入れている人に知らせる）**
  - Web 版のマイページなどで、その人がネイティブ版も使っていれば「アプリのアラームと二重に届くことがあります」と表示し、ブラウザの通知をオフにする方法を案内する。
- **案D（リマインドの通知の見た目で区別できるようにする）**
  - Web Push のリマインドの本文に「（ブラウザからのお知らせ）」と入れるなど、どちらの知らせか分かるようにする。根本の解決にはならないが、手早くできる。

## 当面の対処
- 二重に届いて困るときは、スマホの Chrome の設定で Render のサイトの通知をオフにする。
