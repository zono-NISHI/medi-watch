# 通信できないときもお薬の登録・服薬の記録をできるようにする

開発者から「ネットがつながらなくても、お薬の情報は登録できるようにするべきではないか」という問いが出たことから整理した案。

## 現状
- お薬の登録・変更・削除と服薬の記録は、どれもサーバー（Supabase）へ送って保存する。通信できないときは、エラーが表示されて保存されない。
- ネイティブ版の端末のアラームは、最後に取得した予定を端末に保存しているので、登録が済んだあとは通信できなくても鳴る。
- 通信できないときに服薬を記録しようとすると記録できず、記録しないままになったお薬は5分後にもう一度アラームが鳴る。

## サーバーに保存している理由
- **家族の見守り**：家族の端末は、サーバーにある記録を見て、通知もサーバーから送られる。端末の中だけに保存すると、家族からは見えない。
- **複数の端末**：同じアカウントを、スマホとブラウザなど複数の端末で使える。どの端末で見ても同じ内容にするには、サーバーに1つの正しい内容を置く必要がある。
- **機種変更・故障**：端末の中だけに保存すると、スマホを替えたり壊したりしたときに、お薬と記録がすべて失われる。お薬手帳として致命的である。

## 通信できないときにも使えるようにする場合の課題
- 端末の中に「まだサーバーへ送っていない変更」をためておき、通信できるようになったら送る仕組み（同期）が要る。
- 同じお薬を、通信できない端末とほかの端末（またはブラウザ）で別々に変えた場合に、どちらを正しいとするか（衝突の解決）を決める必要がある。
- 家族への「服薬完了」の通知は、送れるようになるまで遅れる。逆に、本人は飲んで記録したのに、サーバーには届いていないため、家族へ「まだお薬の記録がありません」が送られてしまう。
- 映像つきの記録は、映像のファイルを端末にためておく必要があり、容量を使う。

## 優先するなら、どれからか
- **お薬の登録は優先度が低い。** 登録はたまにしか行わず、病院・薬局の帰りなど、通信できるときに行えば済む。待ってもらっても困ることが少ない。
- **服薬の記録のほうが、通信できないときの影響が大きい。** 記録は毎日、アラームの時刻に行う。そのときに電波が弱いと記録できず、家族へ「まだお薬の記録がありません」が送られる。
- そのため、作るなら「服薬の記録（映像なし）を端末にためておき、通信できるようになったら送る」から始めるのがよい。

## 作り方の案
1. 映像なしの服薬の記録だけを、送れなかったときに端末（localStorage、ネイティブ版は端末の保存場所）にためる。
2. 通信できるようになったとき（`online` のイベント・アプリを開いたとき）に、ためた記録を記録した時刻のまま送る。
3. 二重に送らないよう、記録ごとに端末で ID を付け、サーバーは同じ ID を一度しか受け付けない。
4. ホーム画面に「まだ送っていない記録があります」と表示する。
5. お薬の登録・変更は、これまでどおり通信できるときだけにする（衝突の問題を避けるため）。

## 手間の目安
- 服薬の記録（映像なし）だけ：2〜3日程度。ためる・送る処理、二重送信を防ぐ API の変更、表示。
- お薬の登録まで含めると：1週間以上。衝突の解決、ネイティブ版の端末の予定との整合が必要。

## 卒論での位置づけ
- 「今後の課題」として書ける。
- 「家族と情報を共有するアプリは、サーバーに1つの正しい内容を置く必要があり、通信できないときに使えることと両立しにくい」という点は、考察の材料になる。
- アラームは端末だけで鳴らし（通信できなくても知らせる）、記録はサーバーに置く（家族と共有する）という役割分担を、設計の判断として説明できる。
