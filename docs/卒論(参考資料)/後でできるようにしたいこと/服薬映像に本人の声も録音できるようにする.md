# 服薬映像に本人の声も録音できるようにする

Web 版・ネイティブ版の両方に対する意見から出た案。薬を飲むときに伝えたいことがあれば、映像と一緒に声で家族へ伝えられるようにする。

## 現状
- 服薬映像の録画は音声を録っていない（`public/js/pages/home.js` の `getUserMedia` で `audio: false`）。
- 録画は最大30秒（`MAX_RECORD_SECONDS`）、約1Mbps（`VIDEO_BITS_PER_SECOND`）。
- ネイティブ版はカメラの権限（`android.permission.CAMERA`）だけを宣言していて、マイクの権限（`RECORD_AUDIO`）はない（`mobile/android/app/src/main/AndroidManifest.xml`）。
- 家族への通知は「服薬完了」「服薬映像」など決まった文面だけで、本人が何か伝えたいことがあっても通知からは分からない（`src/services/notificationService.js`）。

## 機能の増やしすぎではないか
- 増やしすぎにはならないと考える。アプリの軸である「見守り」に直接つながるため。
- 高齢の利用者にとって、文字を入力するより声で話すほうがずっと楽。文字の伝言機能より、このアプリの利用者に合っている。
- ただし、録音を足すだけでは「伝えたいことが家族に届かない」ため、下の「気をつけたいこと」の工夫が必要。

## 使えそうな場面

| 場面 | 本人の声の例 | 家族ができること |
|---|---|---|
| 体調の報告 | 「今日はちょっとふらつく」「咳が止まらない」 | 電話する・様子を見に行く |
| 薬が残り少ない | 「この薬、あと3日分しかないよ」 | 薬局・受診の手配をする |
| 飲みにくさ・副作用 | 「この錠剤、大きくて飲みにくい」「飲むと眠くなる」 | 次の受診で医師・薬剤師に相談する |
| 飲んだものを声に出して確かめる | 「白い錠剤を1錠、飲みました」 | 飲み間違いに気づける |
| 安否の確認 | 「おはよう、飲んだよ」 | 声の調子から元気かどうか分かる |

## 気をつけたいこと（作るときの課題）
1. **伝えたいことがあるのに、家族が気づけない**（いちばんの課題）
   - 毎回音声が付くと、家族は伝言があるかどうか分からず、すべての映像を開いて聞く必要がある。
   - 声を入れた記録だけ、通知の文面と記録画面に「🎤 ひとことあり」のような印を出す必要がある。
2. **プライバシー**
   - テレビの音や、同居している人の会話まで入る。
   - 声の録音は最初は OFF にして本人が選んだときだけ録音し、録音中は「声も録音しています」と表示する。
   - 家族に映像を見せるかどうかの設定（`care_group_members.can_view_video`）を、音声にも同じように使ってよいかを決める必要がある。
3. **30秒で足りるか**
   - 薬を飲む動作と話す時間を合わせると、30秒では短いかもしれない。声を入れるときだけ長くするかを検討する。
4. **ネイティブ版の手間**
   - マイクの権限（`RECORD_AUDIO`）を追加すると、許可を求める画面が1つ増える。マイページの「アラームの許可」とは別に案内が必要。
   - `public/` を変えたあと、`npx cap sync android` と APK の作り直しが必要。
   - WebView で `getUserMedia({ audio: true })` が、マイクの権限を宣言するだけで動くかは実機で確かめていない。

## 作り方の案

### 案A：小さく作る（おすすめ）
1. 録画画面に「声も入れる」の切り替え（最初は OFF）を置く。ON のときだけ `getUserMedia` に `audio: true` を渡し、`MediaRecorder` の mimeType も音声つき（例: `video/webm;codecs=vp9,opus`）にする。音声のビットレート（`audioBitsPerSecond`）は 32〜64kbps 程度で十分（30秒で約0.1〜0.3MB 増えるだけ）。
2. 声を入れた記録だとわかるように、`medication_logs` に列を足す（例: `has_voice boolean`）。新しい番号のマイグレーションとして追加する。
3. 声つきの記録のときは、家族への通知の文面を変える（例: 「〇〇さんから、ひとこと（声）があります」）。記録画面・ホームの一覧にも印を出す。
4. ネイティブ版は `AndroidManifest.xml` に `RECORD_AUDIO` を追加し、許可の案内を用意する。
5. `利用者目線のアプリ挙動一覧.md` を更新する。

### 案B：録音の代わりに定型ボタンにする
- 「体調がよくない」「薬が少なくなった」などのボタンを押すと、その内容が家族への通知の文面に入る。
- プライバシーの心配がなく、通知だけで内容が伝わる。ただし細かいことは伝えられない。
- 案Aと組み合わせることもできる（ボタン＋必要なら声）。

## 手間の目安
- 案A：1〜2日程度。録画画面の切り替え、マイグレーション1本、通知文面の分岐、記録画面の印、ネイティブ版の権限が主な作業。
- 案B：1日程度。

## 卒論での位置づけ
- 作れなかった場合は「今後の課題」として書ける。上の「使えそうな場面」で、服薬の確認だけでなく、家族とのコミュニケーションや体調の変化に気づくことにも広げられる点を示せる。
- 「便利さ（声で手軽に伝えられる）」と「プライバシー（周囲の音まで録音される）」の両立、また「情報を足すだけでは家族に届かない（気づける仕組みが要る）」という点は、考察の材料になる。
