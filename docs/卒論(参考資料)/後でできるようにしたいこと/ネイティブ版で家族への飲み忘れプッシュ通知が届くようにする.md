# ネイティブ版で家族への「飲み忘れ」プッシュ通知が届くようにする

## 現状の問題
- ネイティブ版（Capacitor で包んだ Android アプリ）は、Android のアプリ内ブラウザ（WebView）で画面を表示する。
- WebView は Web Push（Push API / Service Worker の通知）に対応していないため、ネイティブ版を使っている家族（見守る側）には、サーバーの cron が送る「飲み忘れ」通知が届かない。
- 当面の対処として、見守る側は Web 版（Render の URL・PWA）を使ってもらう。

## 解決方法：Firebase Cloud Messaging（FCM）を追加する
- FCM は Google の無料のプッシュ通知サービスで、Android アプリへの通知の標準的な仕組み。送信数の上限・料金はない。
- アプリが閉じていても、Android が通知を受け取って表示する（利用者が設定から「強制停止」した場合を除く）。

## 必要な作業
1. Firebase のプロジェクトを作り、Android アプリを登録して `google-services.json` を `mobile/android/app/` に置く。
2. アプリに `@capacitor/push-notifications` を入れ、起動時に通知の許可を求めて FCM のトークン（端末ごとの宛先）を取得する。
3. 取得したトークンをサーバーへ送って保存する。
   - 今の `push_subscriptions` は Web Push 用の列（`endpoint` / `p256dh` / `auth_key` が必須）しかないため、新しいマイグレーションで FCM のトークンを保存できるようにする（例: `kind`（`webpush` / `fcm`）の列を追加し、Web Push 用の列を任意にする、または FCM 用の別テーブルを作る）。
4. サーバーに `firebase-admin` を入れ、Firebase のサービスアカウントの鍵を Render の環境変数に登録する。
5. `src/services/notificationService.js` の `sendToUsers` で、宛先が Web Push なら `web-push`、FCM なら `firebase-admin` で送るように分ける。無効になったトークンは削除する（今の Web Push の 404/410 の処理と同じ考え方）。
6. マイページの「通知を受け取る」の表示・操作を、ネイティブ版では FCM の登録に切り替える。

## 手間の目安
- 1〜2日程度。Firebase の設定（画面操作）、マイグレーション1本、サーバー側の送信処理の分岐、アプリ側のトークン登録が主な作業。
- サーバーの cron や二重送信防止（`notification_logs`）の仕組みはそのまま使える。

## 卒論での位置づけ
- 「Web 版では Web Push、ネイティブ版では FCM」と、同じ通知を端末の種類に応じた仕組みで届ける設計として説明できる。
- Web とネイティブで使える通知の仕組みが違うことは、両者の比較（考察）の材料にもなる。
