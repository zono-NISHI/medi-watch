# 卒論・要旨・パワポを直す手順

このフォルダの卒論本文・要旨・発表スライドを、Claude Code に頼んで直すときの手順です。
道具（スクリプト）とスキルを用意してあるので、毎回一から調べ直さずに直せます。

## 先に準備すること

- **Word と PowerPoint で、このフォルダのファイルを閉じておく。** 開いたままだと上書きできず、「_修正2」のような別名のファイルが増えます。
- PC に Python 3・Node.js・Word・PowerPoint が入っていること（Python の入れ方は下の「Python を入れる」）。
- スライドを作り直す PC で初めて作業するときは、`scripts/thesis/slides` で `npm install` を1回実行する。

## Python を入れる（初めての PC で1回だけ）

卒論本文・要旨（Word）を直す道具は Python で動きます。`python --version` を実行して「Python 3.x.x」と出なければ、次の手順で入れてください。

1. ブラウザで https://www.python.org/downloads/ を開き、「Download Python 3.x.x」（黄色のボタン）を押してインストーラーをダウンロードする。
2. ダウンロードしたファイル（`python-3.x.x-amd64.exe`）を開く。
3. **最初の画面のいちばん下の「Add python.exe to PATH」にチェックを入れる。**（これを忘れると、ターミナルから `python` で呼び出せません）
4. 「Install Now」を押す。「このアプリがデバイスに変更を加えることを許可しますか？」と出たら「はい」を押す。
5. 「Setup was successful」と出たら「Close」を押す。
6. VS Code を一度閉じて開き直す（開いていたターミナルには、新しい設定が反映されないため）。
7. 新しいターミナルで次を実行し、`Python 3.x.x` と出ることを確かめる。
   ```
   python --version
   ```
   - それでも Microsoft Store が開く・案内だけが出るときは、Windows の「設定」→「アプリ」→「アプリの詳細設定」→「アプリ実行エイリアス」で、「アプリ インストーラー python.exe」「アプリ インストーラー python3.exe」をオフにしてから、もう一度ターミナルを開き直す。

追加のライブラリは要りません（道具は Python に最初から入っている機能だけを使っています）。

## どの場面で、どのスキルを使うか

| やりたいこと | 使うスキル | 頼み方の例 |
|---|---|---|
| アプリを直したあとで、論文・要旨・スライドを最新にしたい | `/thesis-check` | 「/thesis-check」「/thesis-check 前回の修正以降の変更だけ見て」 |
| 古い記述がないか調べるだけ（直さない） | `/thesis-check` | 「/thesis-check 調べるだけにして」 |
| 卒論本文・要旨（Word）の決まった箇所を直したい | `/thesis-edit` | 「/thesis-edit 本文の4.5節に○○を追記して」 |
| 発表スライド（PowerPoint）の決まった箇所を直したい | `/thesis-slides` | 「/thesis-slides 6枚目の『8:30』の説明を短くして」 |

スキル名を書かなくても、「卒論の○○を直して」のように頼めば、Claude Code が合うスキルを選びます。確実に使わせたいときだけ `/スキル名` を付けてください。

## おすすめの進め方

### アプリを直したあとで、論文にも反映したいとき

1. `/thesis-check` を実行する。Claude Code が、システムと食い違う記述や、書き足すべき新しい機能・工夫を見つけ、**番号を選ばなくても、本文・要旨・スライドをまとめて直します。**
2. 直した項目の一覧が報告されるので、Word と PowerPoint で開いて、見た目と内容を確かめる。
3. 手直しが要るところがあれば、そのつど「4.6節の追記をもっと短くして」「11枚目の○○は元に戻して」のように伝える。
4. 黄色の蛍光ペン（⟦…⟧）の箇所は、動作確認の状況など、Claude Code がソースから判断できなかった部分です。報告の「確かめたいこと」に答えてください。

- 直さずに一覧だけ見たいときは、「/thesis-check 調べるだけにして」と頼んでください。
- `/thesis-edit` を、直す箇所を書かずに実行したときも、同じように照らし合わせてから直します。

### 直したい箇所が決まっているとき

- `/thesis-edit` か `/thesis-slides` に「どの節（何枚目）の、何を、どうするか」を箇条書きで伝える。これがいちばん速いです。

### 提出用の PDF が要るとき

- 「/thesis-edit 本文と要旨を PDF にして」と頼む（Word のファイルと同じフォルダに書き出されます）。

## 自分で決めて伝える必要があること

次の内容は、Claude Code がソースコードから判断できません。聞かれたら答えるか、先に伝えてください。

- 動作確認をどこまで実施したか（本文の表5.1の「状況」）
- 実施していない検証（iOS、第三者による評価など）
- 反省点・感想など、自分の考えを書く部分

## 気を付けること

- **スライドを PowerPoint で直接直した内容は、スクリプトで作り直すと消えます。** 8枚目に貼った画面の写真も同じです。作り直しを頼む前に、「○枚目は自分で直してある」と伝えてください。
- 卒論本文・要旨は、Word で手直ししてもかまいません。次に直すときは、このフォルダにある最新のファイルを元にします。
- 本文を直したら、要旨とスライドにも同じ記述がないかを確かめます（スキルが確認しますが、最後は自分でも見てください）。

## ファイルの場所

| 場所 | 中身 |

## 発表スライドについて（2026-11-17 に作成）

- 持ち時間12分・13枚。各スライドのノートに、話す内容と時間の目安を入れてあります。
- 8枚目「実際の画面（デモ）」の3つの枠には、アプリの画面の写真を自分で貼ってください（ホーム／撮影画面／家族の表示）。
- 12枚目の「12項目すべてを確認」は、本文の表5.1に合わせています。
